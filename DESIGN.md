# witness — Design

A harness-independent framework (Claude Code and Pi supported; see row 87) that takes a change from **brainstorm → PR** through a six-stage pipeline with five evidence-gated transitions. It synthesizes the best of superpowers (obra), mattpocock/skills, specops (Jarvus), and the axi/no-mistakes CLI family (kunchenguid) into one coherent, self-owned tool.

## North star

Six principles decide every tradeoff below. When torn, favor the earlier one.

1. **State vs motion.** `specs/` describe what must be true (state); `plans/` describe what we're changing (motion). Decompose produces state; plans *derive from* it. Never mixed, never reversed. Specs are **behavior-only** — public surface, never internal interfaces — so refactors don't touch them. This is the spine of the whole design.
2. **Frontmatter is the state.** No state store, no daemon for pipeline position. Every doc self-describes; the CLI derives "where are we" by scanning frontmatter. Committed, git-diffable, resumable. Three kinds of state, never confused: **computed** (derived at scan time, never stored — `blocked`), **stamped** (written by gates — `status`), **cached** (expensive check results stored with an invalidation key — `drift`).
3. **Evidence, then human.** No transition without evidence — deterministic checks + a reviewer verdict. Humans stop where judgment is owed: scope (decompose gate on features), shipping (always), and any blocking finding anywhere. Clean evidence may pass on its own (green path); a human never approves blind, and never rubber-stamps what evidence already settled. Evidence is durable: every check, verdict, and decision lands in the journal.
4. **Clean = single-responsibility.** Each artifact answers exactly one question; no two overlap; one fact has one home; references are one-way. Applied recursively: a fact needed by many specs gets *extracted into its own spec* — this is what killed briefs, stored `blocked`, and multi-parent plans.
5. **Durable where it pays (B-lite).** Spec *depth* is lazy — thin where a slice is trivial, deep where it earns it — but never zero grip: **every spec carries at least one machine-checkable acceptance criterion**. A lying spec is worse than no spec.
6. **Re-entrant everywhere.** Any stage skill, killed at any point and re-run, converges — it detects done-ness from frontmatter plus world state (PR exists, tests pass), never from session memory. Resumability is a testable property, not a hope; the fixture smoke test kills and resumes at every boundary to prove it.

## The pipeline

Six stages, five gates. The agent **auto-advances** and stops per the gate policy below. **Stages shrink, never skip** — every stage always runs, scaled to the change; config controls ceremony, never stage existence.

| # | Stage | Produces | Gate |
| --- | ------- | ---------- | ------ |
| 1 | **brainstorm** | *no canon, only evidence* — stateless interview (grill-me style) ending in a **confirmed scope recap** (class + goals / non-goals / constraints with ids + non-binding slice candidates), persisted by `witness recap` as the birth entry of the **effort journal**; the recap is decompose's input contract and survives session death | none — confirmation is in-conversation; `witness recap` validates the schema (ids unique, goals non-empty), but no reviewer, no stop |
| 2 | **decompose** | **sliced `specs/*.md`** — new specs and/or amendments to living ones, with `summary`, `depends` (the slice DAG), `covers` (manifest-only goal mapping) and **acceptance criteria in the DSL**; written via `witness write --effort` | write-time mechanical checks (schema, DAG acyclic, criteria parse, goal ids exist) + **goal-coverage totality**, set-level and deterministic: every goal covered by ≥1 spec, every spec covers ≥1 goal + slicing critic: truly vertical? independently shippable? coverage *quality*, non-goal violations, criteria adequacy, behavior-only, summary accuracy. **Always stops for `feature` class** — scope is approved *as its concrete slicing* |
| 2.5 | **design** | living approved look `designs/<spec-id>.html` for each `ui`-flagged spec (feature only) | **always stops** — the look is human judgment (same footing as ship); `design-critic` verdict + deterministic checks (artifact self-contained, id-attributed, spec ui-flagged) |
| 3 | **plan** | `plans/<id>.md` with mandatory `parent: <spec-id>` and a `derives-from` content pin; steps are **schema'd in the manifest** (`steps: [{id, title, criteria: [ids] \| scaffolding}]`), body elaborates each in a write-validated `## Step: <id>` section; input = spec + CLI-computed delta | write-time mechanical: **step↔criterion totality, both directions** — every step maps to ≥1 criterion or is marked scaffolding, every criterion has ≥1 step (goal-coverage totality, one level down) + plan critic: faithfully derives the **delta**; step *quality* — testable, honest scaffolding marks |
| 4 | **implement** | code + **spec-tagged tests** (CLI-managed worktree per plan; a fresh **session slice** per **≤`implement.stepsPerDispatch` steps** — the dispatch budget, 79 ✽, relayed via `/clear` (82 ✺); TDD) | battery per change class (see Config); exit bar: tagged tests exist and pass **with recorded red→green evidence per added/modified test**, deterministic drift lane green locally |
| 5 | **ship** | PR + green CI | two-lane drift check + final code-review; **always stops** |

**State leads by construction.** A plan cannot exist without the parent spec it implements — whether that spec is newly created or a living spec amended for this change. "Spec leads" is a structural guarantee, not a rule.

**Change classes.** Every effort carries a class — `feature | fix | chore` — **recorded at recap**; decompose reads it from the effort stream. The class sets the ceremony profile, including **per-class reviewer sets** (see Config):

- `feature` — full interview, full slicing, decompose gate stops for scope approval; full reviewer battery. A `ui`-flagged spec earns the design stage before its plan (row 69).
- `fix` — brainstorm shrinks to a two-question interview; decompose routes to the one amended spec (consulting `witness index`); gates ride the green path with a slimmer battery. **Tripwire:** a `fix` whose manifest *creates* a new spec stops the decompose gate — misroutes usually announce themselves as new specs. **Cold-start note:** on a young canon most fixes legitimately create specs, so this tripwire fires often at first — the dashboard says so explicitly ("canon is young — expect new-spec stops") rather than letting early stops train users that stops are noise. Residual accepted consequence: a *wrong-amendment* misroute is still first caught at the ship gate; the dashboard shows the routing, and autopilot is interruptible. The design stage never arms for `fix` — it rides straight to plan.
- `chore` — motion with **no state change** (deps, tooling): parent = the spec whose implementation area it touches, or `principles.md` for repo-wide work (so `parent: <spec-id | principles>`). **Tripwire:** a chore effort writing any spec content is refused at write time — by definition a class error; reclassify. Principles carry no criteria, so a chore's ship gate has no deterministic drift lane — protection is tests + lint + a one-reviewer battery, and drift is trivially clean by construction. The design stage never arms for `chore` either.

**Multi-slice features.** Decompose emits a **spec DAG** via `depends`. Plans run **sequentially** for now; the DAG already encodes what *could* run in parallel, so drain-the-DAG waves are a later unlock with no data-model change (the write protocol below is already single-writer, so no conflicts either).

**Cross-cutting changes stay per-slice.** A change spanning specs is decomposed as a **sequenced migration** — per-slice amendments ordered via `depends`, expand-contract style (accept both → switch → drop old), each step independently shippable. If the blast radius exists because one fact is written in several specs, decompose first **extracts the shared fact into its own spec** (re-slice via `supersedes`), then amends that one. Plans never get multiple parents.

## Artifact model

```
specs/                 state — living canon of vertical slices (B-lite depth)
  principles.md          cross-cutting rules / trade-offs — type: principles
  <slice>.md             one sliced spec: current desired state of a thin end-to-end slice
                         (globbed specs/**/*.md — id lives in frontmatter, not path,
                         so subdirs are free structure when flat hurts)
designs/               state — living approved look per ui-flagged spec (feature efforts)
  <spec-id>.html         self-contained CLI-written mockup; content sha journaled;
                         gate-approved, stamped design:{sha,spec} on the spec
plans/                 motion — each plan derives from exactly one parent spec
  <plan-id>.md           parent: <spec-id> (mandatory)
.witness/
  journal/<id>.jsonl     evidence — append-only history per artifact AND per effort
                         (effort streams born by `witness recap`), CLI-written (see Evidence journal)
CLAUDE.md              process: how to operate this repo (native Claude Code file)
witness.config.yaml   thin config (see below)
```

**Cut, on purpose:** `briefs/`, `CONTEXT.md`, `docs/adr/`.

- **`briefs/`** — a brief's only unique job is capturing scope *before* slicing; the moment decompose passes its gate, that truth lives more precisely in the specs, and a *living* brief becomes a permanently stale second home for it. So brainstorm persists **no canon, only evidence**: it ends with a confirmed scope recap persisted by `witness recap` as the effort journal's birth entry — append-only history that can't go stale, only be superseded. Scope is approved as its slicing at the decompose gate; the *why* lives in per-spec **Motivation** lines and the decompose commit message. Decompose resumes from the journaled recap after session death, and the dashboard sees in-flight efforts before any spec exists. Remaining accepted cost: a session dying **mid-interview** (before recap confirmation) loses the interview; the ephemeral scratch-dump stays a re-add-on-real-pain option (see Open).
- **`CONTEXT.md` / `adr/`** — their unique jobs don't pay yet; `principles.md` carries standing rules, git/PR history carries the why. Re-add later, append-only, on real pain (term-drift → `CONTEXT.md`; recovering superseded decisions → `adr/`).

### Efforts — the change as a whole

An **effort** is the unit brainstorm→ship runs over: one recap, one decompose, N specs/plans. It is deliberately **not a doc** — no frontmatter, no file in `specs/` — only a journal stream (`.witness/journal/<effort>.jsonl`) born by `witness recap`. Set-level facts live there and nowhere else: the confirmed recap, decompose gate-runs, the goal-coverage mapping.

- **State is entirely derived.** *Active* = recap exists, neither complete nor abandoned. *Complete* = computed at scan: decompose gate passed, every produced/amended spec `live` (or `superseded` by a later effort), every child plan terminal. Never stamped — completion is a fact about artifacts, and a stamp could go stale under late abandonment.
- **Scope evolves via `witness recap --amend <effort>`** — appends a *superseding* recap entry to the same stream (append-only holds; nothing is rewritten). Coverage totality and `covers` validation always read the **latest** recap. An amendment **re-arms the decompose gate's feature-class stop** — scope changed, scope gets re-approved. This is also where revise-upstream lands when decompose-gate findings implicate the scope itself (goals wrong, not slicing wrong): the stop screen offers re-interview → `recap --amend`. Without this verb, the only exit from a mid-effort scope change would be abandoning the whole effort.
- **Slug reuse is refused.** `witness recap` on a slug whose journal stream already exists — active *or* terminal — refuses and demands a new slug; histories never merge silently.
- **Abandonment is explicit** (`witness abandon <effort>`), because a walked-away effort is indistinguishable from not-started-yet forever. Terminal entry in the effort journal; landed artifacts walk the per-artifact abandon path with its refusal rules, or the CLI refuses wholesale and names what blocks.
- The dashboard lists active efforts and their class. No timers, no staleness heuristics — a human abandons dead efforts when the listing annoys them.

### Living canon — what specs mean over time

`specs/` always reads as **current desired state**. History lives in git and the journal, not in doc chains.

- **Routine amendment**: decompose edits the spec's content, flips it `live → approved`, and a new plan (same `parent`) realizes the delta. 1:N plans per spec over its lifetime — even within one effort (expand-contract amends a spec twice).
- **`supersedes`** is reserved for **re-slicing** — when boundaries themselves change (split, merge, extraction of a shared fact). The re-slice **deletes the superseded file** in the same state commit: content survives in git, lineage in the frozen journal (`supersedes:` and `--lineage` resolve against **journal** existence); dangling `depends` edges refuse the commit — dependents are rewritten in the re-slice. `specs/` stays literally "current desired state"; `superseded` is a journal-terminal fact, not an on-disk one.
- **Mid-flight amendment — soft lock**: amending a spec whose child plan is in-progress makes `check` warn and the decompose gate demand explicit ack. Drift always measures against *current* content, so the in-flight plan is caught at its ship gate and routed to revise — and a ship-time revise **re-pins the plan's `derives-from`** to the content it now realizes; the pin must always name what was actually verified, or the next `witness diff` computes its delta from a fiction — so **the CLI stamps the re-pin itself**, from the exact spec content the deterministic drift lane just executed against; a skill-supplied pin would be a reported claim where a witnessed one is available. Honest without blocking course corrections.
- **`live` is a stamped checkpoint**, not cheap derived state: the ship gate stamps it when code demonstrably realizes the content. (Contrast `blocked`, which *is* cheaply derivable and therefore never stored.)
- **Abandonment**: `witness abandon <plan>` flips the plan to `abandoned` and **selectively reverts the paired amendment state commit — spec/plan paths only, journal paths never** (a full revert would erase evidence; append-only wins), restamping the spec's prior status (`live`, if it was live) and appending the abandonment entry. Deterministic precisely because state commits are small and state-only. Refusals, both handed to the human: a later amendment touched the same spec (newest-first only), or other specs `depends` on a newly-created spec being reverted — a deleted dep would block its dependents forever. The canon must never describe unbuilt intent — the canon forgets, the journal remembers the whole attempted cycle.

### Frontmatter — the single source of truth for position

Every doc carries it. The CLI reads and writes it; nothing else stores pipeline position. The schema itself is versioned once, in config (`schema: 1`) — older repo → warn and point at `witness migrate` (reserved); newer repo → refuse with "upgrade witness".

```yaml
# universal
id: auth-refresh                # stable slug — the cross-ref handle (rename via CLI only;
                                # charset [a-z0-9-] write-enforced — ids interpolate into
                                # runner command templates, so the charset is a safety rule)
type: spec | plan | principles
depends: [auth-login]           # INTERNAL DAG: docs that must land first;
                                # persists as the reference graph after landing
                                # (readiness only consults non-live deps —
                                # one field, two phases of one relationship);
                                # record the edge even when the dep is already
                                # live — the reference graph must stay total,
                                # or extraction re-slicing loses its map
needs:                          # EXTERNAL prereqs — tiny check DSL, CLI-evaluable:
  - env: STRIPE_API_KEY         #   env var exists
  - cmd: "npm ls stripe"        #   command exits 0 — confirm-first: new/changed
                                #   cmds prompt once, then join a local
                                #   (gitignored) allowlist; a cloned repo
                                #   never executes silently
  - manual: "Stripe sandbox account created"   # flipped via `witness satisfy` —
    satisfied: false                           # the write path holds even here
```

Per-type:

- **spec** — `status: draft | approved | live | superseded` (`superseded` is journal-terminal — the re-slice deletes the file); `summary:` — required one-liner (≤120 chars, write-validated): what the slice *is*, where Motivation says *why it exists*; feeds `witness index` and the dashboard, accuracy policed by the slicing critic; `supersedes: <id>` (re-slicing only); `criteria:` (the acceptance-criteria DSL, below); `drift: {sha, at}` health flag set/cleared by reconcile — status stays `live`, because lifecycle ≠ health; `ui: true` (optional, spec-only, boolean — a slice that changes browser-rendered/interactive behavior; set at decompose, slicing-critic-policed both directions; earns the design stage); `design: {sha, spec}` (**volatile** cached-state stamp — approved artifact sha + the spec content sha it was designed against; written only by the design gate's approve path; scan derives `design-pending` = feature-effort + `ui: true` + missing/stale stamp); body is **template-validated**: `## Motivation` and `## Behavior` headings required at write — doc-gate anchors get guaranteed targets, prose stays free inside.
- **plan** — `status: draft | approved | in-progress | done | abandoned`; `parent: <spec-id>` (**mandatory, singular**; `principles` allowed for chores); `derives-from: <content-sha>` — the exact spec content this plan realizes (canonical content sha — volatile fields excluded, see Evidence journal); `design-from: <artifact-sha>` — **mandatory when the parent spec is `ui`-flagged** (must equal the parent's current `design.sha`; the plan gate re-checks), refused on a non-ui parent; `pr: <n>` set **at PR creation**; body carries one `## Step: <step-id>` section per manifest step (write refuses missing/orphan — step↔body totality).
- **principles** — `status: draft | approved`; exempt from readiness and drift.

**`depends` vs `needs` is the core distinction.** `depends` is the internal readiness graph the CLI walks; `needs` is the external world, every entry machine-checkable or an explicit manual flag. A doc is *ready* only when both are clear. **`blocked` is computed at scan time, never stored.**

### Acceptance criteria — the deterministic lane's contract

Criteria get the same discipline as `needs`: a tiny DSL, every entry machine-runnable. Free prose is not a criterion.

```yaml
criteria:
  - test: "@spec:auth-refresh"   # all tests tagged with this spec id must pass
  - cmd:  "npm run smoke:auth"   # exits 0
```

- **Test tagging.** Implement tags every new test with the parent spec id — **in the test name/title** (`it("rotates token before expiry @spec:auth-refresh")`), never a comment: names are the one string that test filters (`-t`/`-k`), test reports, and grep all see; comment tags would demand a per-framework source→report correlation swamp. The CLI's matcher normalizes case and `-`/`_` so name-hostile languages work (`test_rotates_token__spec_auth_refresh`). Verification is **bidirectional**: every live spec has ≥1 passing tagged test (read from the report); no tag points at a nonexistent spec (source grep, respecting `.gitignore` plus configured excludes — vendored dirs and fixtures would false-positive). Renaming a test never touches the spec — the tag travels with the code, so behavior-only specs (north star 1) survive refactors. A failing test announces which spec it guards; the tag being visible in output is a feature.
- **Execution — two modes, one config key.** `criteria.runner` is either a filtered template (`npm test -- -t "@spec:{id}"` — the fast path for one spec's gate) or `full-suite` + `report: junit:<glob>` (one suite run mapped to all tags — what `check --drift` across the whole canon wants anyway, and the zero-framework-knowledge fallback; the glob matters: recursive monorepo runners emit one report per package, and the CLI **merges** them). The filtered template's contract is explicit: **root-runnable**, args forwarded through recursive runners, passes with zero matching tests (`pnpm -r` + vitest wants `--passWithNoTests`). Multiple runners per repo: deferred with `ship.test`'s singular shape.
- **Command trust.** Every command witness executes — `criteria.cmd`, `needs.cmd`, and config commands (`ship.test`, `ship.lint`, the runner) — passes **one prompt-once allowlist** (local, gitignored, keyed by command string): first run in a fresh clone confirms the full set, new/changed commands re-prompt. CI opts in explicitly (`WITNESS_TRUST_CMDS=1`) — a cloned repo never executes *anything* silently, and a repo's CI trusting the repo's own commands is consent, not a hole (a committed allowlist would add ceremony, not trust: the attacker's PR carries both the command and its entry).
- **Red→green evidence.** A tagged test that *passes* proves existence, not relevance — assertions can rot while the tag stays green forever. `witness test-evidence` records **CLI-witnessed** runs at the TDD loop's natural red and green points (the CLI executes the runner and observes; the evidence is not skill-reported). The implement gate requires the **fail-before/pass-after pair for every tagged test the plan's diff adds or modifies** — prompt discipline enforced by mechanism. Missing evidence? `witness verify-red` reconstructs it: stash the diff's non-test files back to base, run (expect red), restore, run (expect green) — safe in the plan's isolated worktree. A "new" test that's green against base code is surfaced as a stop: the test may be vacuous, or the behavior already existed. Pure-`cmd:` criteria and untouched tests need no evidence — the requirement rides the diff, not the spec's history.
- **UI behavior is browser-witnessed, end-to-end.** A plan step that changes user-visible browser behavior TDDs at that surface: its red is a **Puppeteer** test driving the real UI **through the whole slice** — everything the repo owns (frontend, backend, persistence) runs real; fakes are legitimate only at boundaries the repo doesn't own (third-party services), so the test stays runnable in any clean worktree while still proving the slice whole. Headless, tagged and evidence-witnessed like any other test. Puppeteer over runner-shaped tools deliberately — it is a library, so browser tests live inside the single `criteria.runner` the evidence machinery already reaches (multi-runner stays deferred; a browser test *outside* the runner would be structurally unwitnessable — `test-evidence` can't execute it, so the implement gate's red→green requirement refuses the diff anyway). Browser tests own the slice's lifecycle — boot backend + store and serve inside the test, never presume a dev server — or they can't run root-level in a clean worktree. The mandate is **motion-side only**: the implement protocol carries it, plan steps name the browser test, and the pr-test lens treats unit-for-browser substitution — and its mirror, a browser test over a stubbed own-backend — as critical gaps; spec content and the DSL stay untouched — *what kind of test* proves a behavior is HOW, and specs are behavior-only (north star 1).
- **Lifecycle.** Criteria are promises at decompose and obligations at ship: decompose gate → criteria **parse**, adequacy reviewed by the slicing critic (a criterion that can't fail is not a criterion; and a `cmd:` criterion must state its expected behavior in the spec's `## Behavior` section — the template guarantees the home exists (60), the critic polices that the fact lives there; a threshold that lives only inside the script is a fact with a hidden home, and it drifts invisibly); implement exit → tagged tests **exist and pass with red→green evidence** (plus a local run of the full deterministic lane, so ship confirms rather than discovers); ship gate and reconcile → criteria **pass**. Drift-check entries record the per-spec **tag count**, so silent tag attrition (12 tests → 1 across a refactor) trends on the dashboard instead of hiding behind the last green survivor.
- Criteria live in frontmatter, authored by decompose, written by the CLI via the manifest (below).

### Evidence journal — where history lives

`.witness/journal/<id>.jsonl` — append-only, one file per **artifact** and one per **effort** (set-level facts — the recap, decompose gate-runs, the goal-coverage mapping — live in the effort stream; artifact-level facts in artifact journals; `run_id`/`caused_by` stitch across; one fact, one home). Written only by the CLI, committed with state commits. **Never compacted or rotated — deliberately**: append-only JSONL diffs cleanly and compresses well; immutability is worth more than the disk. **Frontmatter is position; the journal is history.** Without it, "evidence accumulates across rounds" and the 3-round bound would silently reset with every session.

Seven entry types — `recap` / `gate-run` / `human-decision` / `drift-check` / `test-evidence` / `adopt` / `write-refused` (a `recap --amend` appends another `recap` entry — same type, latest wins; `write-refused` is the lightweight authoring-time record — per-violation rules, no content — that lets the dashboard trend first-try valid rate):

```jsonl
{"v":1,"t":"recap","effort":"auth-hardening","class":"feature",
 "goals":[{"id":"g1","text":"Refresh tokens rotate before expiry"}],
 "non_goals":[{"id":"n1","text":"No SSO provider changes"}],"constraints":[],"slices":["token rotation"]}
{"v":1,"t":"gate-run","gate":"plan","artifact":"auth-refresh-plan-2","round":1,
 "run_id":"r-8f2","artifact_sha":"9f3c21e","reviewed_sha":"9f3c21e","witness":"0.4.1","model":"claude-fable-5",
 "checks":[{"name":"schema","ok":true},{"name":"steps-map-to-criteria","ok":false,"detail":"step 4 unmapped"}],
 "verdict":{"coverage":[{"anchor":"## Context","note":"read"},{"anchor":"## Step 4","note":"see finding"}],
  "findings":[{"blocking":true,"anchor":"## Step 4","claim":"assumes token table exists; AC-2 creates it here"}]},
 "outcome":"stopped"}
{"v":1,"t":"human-decision","gate":"plan","artifact":"auth-refresh-plan-2","round":1,
 "decision":"revise","note":"token table exists in prod; plan against migration 0042"}
{"v":1,"t":"test-evidence","artifact":"auth-refresh-plan-2","phase":"red","runner":"filtered",
 "tests":[{"name":"rotates token before expiry @spec:auth-refresh","ok":false}]}
{"v":1,"t":"drift-check","artifact":"auth-refresh","artifact_sha":"4e7ab90","tags":7,
 "criteria":[{"test":"@spec:auth-refresh","ok":true},{"cmd":"npm run smoke:auth","ok":false}]}
```

Rules that make it survive everything:

- **Content-sha pinning.** Entries reference content by hash — never claims about "current" content, so amendments can't invalidate history, and "has this changed since the verdict?" is one hash compare. Doc content uses the **canonical content sha**: hash of body + non-volatile frontmatter, with the volatile fields (`status`, `drift`, `pr`) excluded — a status stamp or drift flag must never invalidate a verdict, a `derives-from` pin, or a `witness diff` base (one definition, four consumers: pins, verdict keys, round counting, diff). Code is referenced by **worktree tree-sha**, computed through a **temporary index** (`GIT_INDEX_FILE=<tmp> git add -A && git write-tree`, honoring `.gitignore`, real index untouched) — untracked files are part of what was judged; a protocol test asserts an untracked-only revise changes the sha. Raw `git hash-object` blob shas appear only where a real git object is needed.
- **Ordering is derived, never stored.** Appends travel in state commits; single-writer main makes commit order the total order across all journal files — and because order stays *derived*, the deferred team future re-derives it (topological commit order) instead of migrating stored sequence numbers; storing order "for convenience" would be the regression. `witness log --all` merges by it. `run_id` stitches entries born of one CLI invocation; `caused_by: {artifact, gate, round}` back-references cross-artifact causality (revise-upstream writes the reopen entry in the parent's journal, linked, never duplicated).
- **Immutable.** `migrate` never rewrites entries; each carries its own `v`. Re-slicing freezes the old spec's journal; `witness log <id> --lineage` walks the `supersedes` chain. Renames are a CLI verb (`witness rename <old> <new>`) that moves the journal and rewrites references in one state commit; `check` flags orphan journals.
- **Verdicts are cached state.** A gate invocation whose key — (**reviewed sha**, gate, reviewer-set hash, model, witness version) — matches a prior gate-run entry **reuses that verdict** — no reviewer re-roll; **the cache governs invocation only**: a reviewed sha equal to the *last* entry's is a resume and appends nothing (the existing entry *is* the evidence), while a different sha appends a new gate-run entry carrying the cached verdict marked `cached: true` — a counted round either way, and the journal already records every key component. **Reviewed sha is per-gate**: canonical content sha of the artifact for the doc gates (decompose, plan); **worktree tree-sha for implement and ship** — the key must bind to what the reviewers actually judged, or an implement revise that changes only code (plan doc untouched) would cache-hit a stale verdict on old code and rounds would never count. **Reviewer-set hash covers prompt *contents*, not names** — lenses are configurable, so a set-membership hash would let an edited lens dodge the key. `--fresh` forces a re-roll for a human who distrusts the cache. Judgment becomes deterministic on re-entry — north star 6 for the verdict lane, not just the deterministic one.
- **The revise hand-off channel.** Revise re-invokes the stage skill with the last verdict + human note — reconstructed from the journal, not session memory, so revise survives session death. Round counter = **gate-run entries since the last approve** (same-sha re-entries append nothing) — revise rewrites the reviewed content (doc or code), so real rounds count themselves; re-rolls and resumes are free, and returning to *previously seen* content still appends (cached verdict, new entry), so A↔B oscillation cannot dodge the bound. A revise that lands **identical content** (reviewed sha unchanged) is surfaced as an explicit *"revise changed nothing"* stop — otherwise the cache would return the same verdict, the round would never count, and the human would loop forever with the bound never tripping. The 3-round bound is real across sessions.
- **Excluded, deliberately:** full reviewer transcripts, full test output (summaries + exit codes; CI run URL at ship), artifact content (shas point into git), decision rationale prose (Motivation lines and commit messages — one fact, one home).

### State-write protocol

**The CLI is the sole writer of `specs/` and `plans/` — all content, not just frontmatter.** Skills author; the CLI writes:

- **Manifest handoff.** A skill emits a body (scratch file) + a structured manifest (id, summary, depends, needs, criteria, covers) and calls `witness write <id> --effort <e> --meta m.json --body b.md` — the effort hands the CLI the recap to validate against; several efforts can be in flight, so it is never inferred. Validation runs **before** the write — schema, DAG acyclicity, criteria parse, `covers` ids exist in the recap, `summary` present and ≤120 chars, class tripwires (a chore writing spec content → refuse) — so illegal artifacts never exist on disk, and part of each gate's deterministic checking moves to authoring time (gates re-run the checks; they're cheap and idempotent). Refusals are **structured errors** — `{field, rule, got, want}` per violation, built for model self-repair; a stage skill gets **3 write attempts**, then stops for a human with the list (the gate bound's authoring-time twin); every refusal appends a `write-refused` entry to the effort journal, so the dashboard trends **first-try valid rate** — the production mirror of the calibration metric (61).
- **Enforced twice.** Real-time: the plugin ships a **PreToolUse hook** blocking direct Edit/Write on `specs/**` and `plans/**` — whole directories, no region parsing — plus best-effort matching of Bash commands touching those paths; the model gets "use witness write" as feedback. The hook is **friction; the audit is the guarantee**: state commits carry a `Witness-State: 1` trailer, and `witness check` audits that spec/plan diffs appear only in trailer-bearing commits — catching hand-edits, Bash end-runs, and hookless sessions.
- **Audit findings get a mechanical exit: `witness adopt <path>`.** Re-validates the hand-edited content (schema, criteria parse, class tripwires — the same checks `write` runs), wraps it into a proper trailer-bearing state commit, and appends an `adopt` journal entry; or offers revert. Adopting a **live** spec whose canonical content sha changed runs the deterministic lane on the spot: pass → stays `live`, the entry records the re-verify; fail → `drift` stamps immediately (**no debounce** — a hand-edit is known-changed content, not a flaky suite). A criteria-unchanged prose edit stays `live` with `unreviewed-amendment: true` on the entry, dashboard-surfaced as reconcile work — an adopted edit is never silently pristine. Humans *will* fix typos in their own canon from their own editor — the audit without a fire exit would make the honest path more expensive than the bypass, which is how tools train users to route around them.
- **State always lands main-side, from anywhere.** A CLI invocation inside a linked worktree (implement's gate-runs, test-evidence) detects it and routes state writes through the primary checkout — otherwise implement's own evidence would ride the PR branch, violating code-only branches.
- **One clone, one writer — enforced, not assumed.** `.witness/lock` (pid + stale detection) serializes state writes across concurrent sessions on the same clone; two terminals on one repo is a Tuesday, not a deferred team scenario.
- **Writes are transactional.** A crash between artifact write and state commit leaves dirty state paths with no trailer commit; the next invocation detects exactly that signature and offers complete-or-rollback — the CLI honoring the same re-entrancy invariant it demands of skills.
- **Commits are path-scoped** (`specs/`, `plans/`, `.witness/` only); the CLI refuses to commit if those paths are dirty with unrelated changes. Stages 1–3 artifacts are gate-approved on main — the gate *is* their review.
- **PR branches carry code only, never spec/plan changes.** During the PR window the plan correctly reads `in-progress` on main. The ship drift lane reads spec content **from main, never the PR-branch copy** — the branch copy is stale under a mid-flight amendment.
- **Post-merge stamping is lazy.** No daemon: any CLI invocation that scans and finds an in-progress plan with `pr: <n>` queries `gh`; if merged → stamp `plan → done`, `spec → live`, append journal entry, commit. Stale-until-next-scan, always self-healing — the same philosophy as computed `blocked`. Offline or rate-limited, the query times out quietly to "stale, couldn't check" — a scan (and SessionStart's dashboard) never hangs on the network.
- **`sync`** = pull --rebase, then push accumulated state commits. State commits are local-first; pushed at ship or explicit sync. Single-writer by construction — future parallel waves cannot conflict on state.
- *Deferred limitation:* team repos with protected main need state to travel via PR — out of scope until the tool targets teams. (Same for one user on two machines: single-writer holds per-clone; a rejected push is the detection signal.)

## Orchestration

**Hybrid hub.** One entry point, always-visible state, one coherent voice across all stages (the axi promise).

- **CLI `witness`** (deterministic, axi-styled — TOON output, no-arg dashboard, `help:` hints):
  - scan frontmatter → **dashboard** (where you are, the one next action; active efforts and their class; blockedness computed live; drifted specs surfaced as reconcile work; multiple ready specs → it asks rather than guesses)
  - `recap` (validate + persist the scope recap; births the effort journal; `--amend` appends a superseding recap to a live effort) · `next` (run the next stage) · `check` (schema, deps, `needs`, transition legality, `gh` + `claude` presence/auth, trailer audit, orphan tags/journals) · `check --drift [--deep]` (reconcile — see Gates; **read-only in CI**) · `write` (manifest → validated artifact) · `adopt <path>` (re-validate + adopt a hand-edit as a state commit) · `design <spec-id> --file <html> | --reconfirm` (persist the look / re-stamp a no-visual-delta amendment) · `diff <spec>` (delta since last realized state: previous plan's pin → last live stamp → empty for new specs) · `index` (id · summary · status · depends across the **live** canon, grouped by dir — computed, never stored) · `satisfy` (flip a `needs.manual`) · `test-evidence` / `verify-red` (red→green witness — see Acceptance criteria) · `abandon <plan|effort>` · `rename` · `sync` · `clean` (reap stray worktrees) · `calibrate <model>` (tier-2 fixture suite vs a named model → matrix entry; local overlay gitignored, gate-runs it clears stamp `calibration: local`) · `log <id>` (render journal; `--all`, `--lineage`) · `init`
  - **no generation, refined: the CLI never *authors* content** — pure state computation and deterministic ops. Deterministically invoking a pinned reviewer prompt at a gate and capturing its structured output is orchestration, not generation (see Gates) — the distinction that lets verdicts be CLI-witnessed without the CLI ever freehanding a word.
- **Skills** (generative): brainstorm (stateless interview → confirmed recap → `witness recap`), decompose (routes via `witness index`), design (`witness-design` — interactive two-mode look session for `ui`-flagged specs: context → 2–3 distinct directions → converge → self-contained HTML with id-attributed sections; hands the CLI the artifact, never touches `designs/` directly), plan, implement, ship. Each does model work; **skills never touch `specs/` or `plans/`** — they hand the CLI manifests — **and never carry verdicts**: gate reviewers are invoked by the CLI, not spawned or relayed by the stage skill (see Gates).
- **Slash command `/witness`**: the engine — asks the CLI for the next action, invokes the matching stage skill, loops; stops per gate policy. `--manual` makes every gate stop for this run — caution is a per-session mood, not a repo property, so it's a flag, not config.
- **Hooks**: SessionStart injects the dashboard; PreToolUse guards the write path.

**Autopilot — green path.** The agent drives stage→stage. A gate **auto-passes only when every deterministic check is green AND the verdict has zero blocking findings** — notes don't stop the pipeline; they land in the journal and surface on the dashboard while the artifact is non-terminal (after that, `log` keeps them — the dashboard shows work, not archives). Any blocking finding is a hard stop with full context (`approve · revise · stop`). Standing stops regardless of evidence: the **ship gate always stops**; the **decompose gate stops for `feature`-class changes** (scope is human intent) and for a **`fix` that creates a new spec** (misroute tripwire); the **design gate always stops** for `ui` specs (the look is human intent). The green path needs no flag — it is the default behavior; `--manual` is the only mood switch.

## Gates

Every transition is **evidence-then-human**, with the green path as the fast lane:

1. CLI runs the stage's deterministic checks (many already ran at write-time; re-running is cheap and idempotent).
2. **The CLI invokes the reviewer(s) itself** — headless (`claude -p`, never a Task subagent — 82 ✺), vendored prompt, artifact read from disk, structured output enforced — resolved per gate *and change class*. **Verdicts are CLI-witnessed, never skill-relayed** — the exact discipline `test-evidence` already has: the orchestrating agent can neither doctor what reviewers see nor fabricate what they said. The gate lane was the last place where evidence was model-*reported* rather than CLI-*observed*; under autopilot pressure ("work's done, just need the gate green") the relaying agent is precisely the adversary the write path already assumes. `witness check` probes `claude` presence/auth like `gh`. Reviewers produce a **structured verdict** — findings as `{blocking, anchor, claim}` **plus required `coverage: [{anchor, note}]`** (resolvable anchors over the reviewed content — proof the artifact was actually read; minimum per artifact kind); the CLI validates that every anchor resolves in the reviewed content, so hallucinated findings die mechanically — and a **clean verdict with missing or unresolvable coverage is malformed**: `findings: []` is the easiest verdict to fake (a "report clean" instruction injected via the reviewed content rides one hop past the relaying-agent adversary) and was the only uncheckable one; injection twins in the calibration suite (Decision 56) assert planted defects survive an embedded report-clean instruction. **Anchor grammar is per artifact kind**: doc gates → heading path; code gates → file path + optional symbol, grep-resolved, **never line numbers** (they drift across revisions, and a fail-closed check over brittle anchors would false-stop honest verdicts until stops read as noise). **Omission findings are first-class**: `anchor: {kind: omission, scope: <file | section>}` — scope must resolve; "no timeout anywhere" is the most valuable genre of finding and must be expressible, and a blocking omission stops the gate like any other (never auto-dismissed for anchorlessness). **Fail-closed on malformed verdicts:** a finding whose anchor doesn't resolve rejects the *whole* verdict — never silently pruned (a pruned real finding would let the green path pass on a false clean) — and stops the gate for a human with the malformed verdict attached. Verdicts are **cached state** (see Evidence journal): re-entry on unchanged reviewed content reuses the journaled verdict; `--fresh` re-rolls; entries stamp the **model id** alongside the plugin version, so calibration drift is diagnosable post-hoc. **Reviewer model is pinned** — the CLI invokes reviewers, so it controls the knob: `gates.model` (exact id, aliases refused), default = the matrix's best; fallback chain **pinned → next available calibrated id → session default + floor warning**. **Model floor** (the chain's last rung): a gate-run on a model outside the shipped calibration matrix (Decision 41) is flagged in the journal entry and warned loudly on the dashboard (`--manual` treats it as a stop) — calibration binds nothing if the model is one nobody measured; `witness calibrate` regenerates the matrix per model, and a self-calibrated (local-overlay) floor stamps `calibration: local` on every gate-run it clears. Reviewer prompts are calibrated to one bit: *blocking = you would block a merge over this* — and that calibration is regression-tested against planted-defect fixtures (Decision 41). (Lenses configurable per gate; defaults vendored in; the verdict-cache key hashes lens *contents*, so a customized lens is a different reviewer.)
3. Green (all checks pass, zero blocking findings) → auto-pass, unless this gate is a standing stop. Otherwise: dashboard shows checks + verdict + artifact; human chooses `approve · revise · stop`. Notes append to the journal either way.

**Revise semantics.** `revise` re-invokes the *same* stage skill with the reviewer verdict + the human's note attached — reconstructed from the journal, so it survives session death; the artifact updates in place (via `witness write`) and the gate re-runs. Evidence accumulates in the journal across rounds. Hard bound: **3 rounds per gate** (rounds = **gate-run entries since the last approve** — same-sha re-entries append nothing, so re-rolls and resumes are free; identical content is an explicit "changed nothing" stop; *previously seen* content re-appends with its cached verdict and counts, so A↔B oscillation trips the bound — see Evidence journal), then the gate refuses to loop and forces a human decision (approve-with-override or stop). When findings implicate an earlier artifact — code faithful, plan wrong — the stop screen offers **revise upstream**, reopening the parent artifact's stage with a `caused_by` link in both journals; from the decompose gate, upstream means the scope itself — re-interview via `recap --amend` (Decision 52).

**Two-lane drift check (ship gate).**

- **Deterministic lane (fail-closed):** the CLI executes the parent spec's criteria — tagged tests and commands, read from main. Unit-testable, reproducible, blocks on failure.
- **Reviewer lane (advisory):** a headless reviewer judges semantic drift between prose and code; blocking findings stop the gate for human judgment, never silently block.

Because every plan has a parent spec, there is no "slice with no spec" case to slip through.

**Design gate.** Reviewed = the artifact (`designs/<spec-id>.html`) + the parent spec; standing stop always (same footing as ship — the look is human judgment, not evidence-gated). Approval (via `decide --approve`) stamps `design: {sha, spec}` onto the spec and journals a `design-stamp` entry. Revise-upstream splits by cause: slicing wrong → reopens the effort's decompose; scope wrong → `recap --amend`.

**Sight witness (design gate).** A standing stop is only human judgment if the human was shown the thing. Sight is a **precondition of gating**, not a byproduct of it: `witness design <id> --open` spawns the platform opener on `designs/<spec-id>.html` and journals a `design-shown` entry carrying the artifact's sha, the opener command it resolved, and the `user@host` it ran on. `gate design` refuses **`design-unseen`** from `resolve()` — before any reviewer is invoked, so the refusal is free — and `decide design --approve` refuses the same way, because the gate does not run at the round bound and approve is the act that stamps. `next` routes a registered-but-unshown artifact to `--open` by name. Sha-keying is what survives revise rounds: re-authoring invalidates prior sight exactly as re-capturing invalidates a witnessed screenshot (Decision 71). The act lives in the CLI, not the skill, for the same reason verdicts do (Decision 48) — but the CLI *refuses without it* rather than performing it during the gate. Gate-time spawning was designed and rejected: `runGate` calls `resolve()` before four short-circuits that write no entry (resume, changed-nothing, bound, malformed-streak), so the window would open on paths the journal never learns about — including the case where a human re-runs the gate after fixing their opener, reads the artifact it opens, and is then told by the replayed entry that nobody has seen it. Refusing keeps the effect and the record at one site. The principle the incident actually teaches is *silent versus loud*, not *who acts*: an agent that drops the show step now hits a loud refusal its repair loop already handles. **What this witnesses is a spawn on the machine the CLI ran on, not perception** — over SSH or in a container it shows nobody anything, and `WITNESS_OPENER` can be pointed at a no-op. That is why the resolved command and host are on the record: a degenerate opener reads as a degenerate opener in the journal instead of being blessed by a flag named "suppressed". **The design gate gets no vision lens.** Presentation is judged by the human here (the gate always stops, so a human is present by construction) and by the vision `design-reviewer` at implement (which can pass unattended, so nobody is). `design-critic` stays a **source** lens — coverage, canon, realizability; it is not blind to presentation by defect, it is scoped away from it by design.

**Design lens (implement gate).** When a plan pins a `design-from` design (part 2 — the plan is UI-work), the implement battery adds a **vision `design-reviewer`** over the browser e2e's witnessed screenshots. The CLI exports `WITNESS_SCREENS_DIR` to the runner during `test-evidence` and clears it per cycle, so captures are latest-cycle by construction; each PNG's sha is journaled on the `test-evidence` entry (the same CLI-witnessed trust chain as red→green — a hand-swapped screenshot refuses `capture-sha-mismatch`). The reviewer reads the captures by path (multimodal `claude -p`, Read tool) and judges them against the injected `docs.design` canon and the living `designs/<spec>.html` — the approved *direction*, never pixel equality — with generic UX heuristics as the baseline where the repo has no canon. Anchors are capture filenames; a blocking finding stops the gate like any other. A UI plan with zero verified captures refuses `screens-matched-nothing` before a reviewer is invoked; a feature/fix plan that is not UI-work drops the lens, journaled `skipped` (stages shrink, never skip). The living design's contents hash into `prompts_sha`, so an amended design re-rolls a cached verdict on unchanged code.

**Reconcile — out-of-band changes.** Commits that bypass the pipeline (human hotfixes) rot specs silently between ship gates. `witness check --drift` runs the deterministic lane across every live spec at any time — cheap, CI-schedulable, **but CI runs it read-only**: nonzero exit + report, never a journal append or flag write (CI as a second writer would break single-writer main); the next *local* run stamps — stale-until-scan, the lazy-stamp philosophy again, with CI's own red status as the notification channel in between. `--deep` adds the reviewer lane for a chosen spec. **The `drift` flag is debounced**: every local run journals its `drift-check` entry, but the spec's `drift: {sha, at}` flag (status stays `live` — lifecycle ≠ health) is stamped only after **two consecutive failing local runs** — a single red surfaces on the dashboard as "seen red once, unconfirmed", not a state commit. Fail-closed lanes meet flaky suites in the real world; a flapping flag is commit churn that trains users to ignore red, which is how deterministic lanes die. The flag clears on the next passing run. The dashboard trends flap frequency from drift-check history — a criterion that keeps flapping is itself reconcile work (fix the test or the spec). Per-criterion `retries:` is deferred to real pain.

## Ship

**Ship is a skill; the CLI does the deterministic steps.** The skill orchestrates: run tests → run lint → deterministic drift lane → `gh` PR create (records `pr:` in the plan) → **mechanical rebase if main moved → watch CI** (rebase before the watch, or the watched run is stale) → always stop for the human. On a real (semantic) conflict the CLI reports and hands control back to the skill — the agent resolves, then re-invokes the CLI to continue. The CLI's "no generation" definition stays exactly true. Ship is re-entrant: killed mid-watch, a re-run resumes from `pr:` + world state.

**Worktrees are CLI-managed.** Created at implement start (path recorded in the journal), reaped when the plan reaches a terminal state — the lazy stamp noticing the merge, or `abandon` (branch ref kept for archaeology, worktree deleted). `witness clean` sweeps strays.

**No orchestrator binary; `gh` and `claude` are declared requirements** — `gh` for PR operations, `claude` for CLI-invoked gate reviewers (Decision 48). `witness check` probes presence + auth for both; if absent, the affected step stops loudly with help text (ship at PR creation; any gate at reviewer invocation).
