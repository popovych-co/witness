**Goal:** Close the three open issues as one patch release, 0.25.1:
- **#58:** a host's sleep stops counting as session time;
- **#59:** drive keeps a Windows host awake;
- **#60:** at the code gates, a delta round's coverage floor counts the change, and a re-gate after a malformed round re-asks only the lenses that failed.

**Architecture:**
- **Part 1 (rows 208–209, #60).** Task 1 gives a delta-mode lens at a code gate a `floor`: the paths the change since the base round touched. `verdictViolations` counts it, and `resolveAnchor` accepts its paths. Task 2 gives `appendKind` a `repair` kind for a malformed last round. When the key and the full prompts are the same, only the lenses without a verdict are invoked, and the rest are carried.
- **Part 2 (row 210, #58).** Task 3 replaces `spawnSession`'s one `setTimeout` with a ticking clock on a monotonic ticker that measures awake time. A check that arrives more than 30 s late counts as sleep.
- **Part 3 (row 211, #59).** Task 4 adds a win32 branch to `keepAwake`. System32 Windows PowerShell 5.1 holds `SetThreadExecutionState` until drive's pid exits. A helper that dies early prints `keep-awake: lost`.
- **Wrap-up.** Task 5 writes the DESIGN rows. Task 6 verifies, reviews, has the human measure on Windows, and releases.

## Verified evidence base

### E1 — #60's root cause (read, probe P2)

- **The floor counts the full diff.** `verdictViolations` (`src/verdict.ts:320-331`) counts coverage anchors over `reviewed.files` and wants `min(5, files.length)`. At implement, `files` is every path changed vs base (`src/gates/implement.ts:100,172`).
- **The delta round keeps that floor.** It keeps that `reviewed` (`src/gate.ts:466`), while its block says the round "judges what changed" and that "the verdict contract applies to it unchanged" (`src/delta.ts:168`).
- **P2.** Setup: the `vitest-single` fixture changes 4 files vs base, round 2 edits only `src/token.ts`, and every lens covers exactly that file. Result: round 2 has `delta: {round: 1}` and is `malformed`. All four lenses took the reroll and still answered `coverage-minimum: 1 distinct changed files covered / ≥ 4 coverage anchors naming distinct changed files`.
- **A deleted file cannot be anchored.** A delta's paths can include a file round 1 added and the revise deleted. It is in `changedPaths(base.reviewed_tree, tree)`, but in neither `files` nor on disk, so `resolveCodeAnchor` refuses it (`src/verdict.ts:185`). That is D162's unsatisfiable-floor class.

### E2 — Re-gating after a malformed round re-shows it (read, probe P1)

- **The resume branch lacks the malformed check.** `appendKind`'s first branch resumes the last run whenever it has the same key and did not fall back (`src/rounds.ts:421-426`). Unlike the cache scan (`:436`), it does not skip a malformed run.
- **P1.** Setup: the synthetic plan gate, a verdict under the floor, then a valid verdict, with the content unchanged. The second run printed `round: 1 of 3 (resume — content unchanged)` and `outcome: malformed`, journaled nothing and invoked no lens, while its own block said "re-running is free".
- **The streak test needs `--fresh`.** The `malformed-streak` test can produce two malformed rounds only with `fresh: true` (`tests/gate-engine.test.ts:224-225`).
- **So the re-run never happens.** Row 126's "the recommended act is the re-run" re-ran nothing. Issue #60's next run re-ran all five lenses only because the content had moved.

### E3 — #58's root cause, and two more facets (read, issue timeline, probe P4)

- **One timer per session.** `spawnSession` arms one `setTimeout(stop, sessionTimeoutMs)` (`src/drive.ts:254`) and reports `ms = Date.now() - t0` (`:174-176`).
- **Windows timers count suspend.** In issue #58's timeline, the timer fired 10 s after a 9 h sleep, with about 24 s of awake time.
- **macOS and Linux timers probably don't.** libuv's `uv__hrtime` reads `mach_absolute_time` / `CLOCK_MONOTONIC`, which stand still in suspend. This was not probed, and Task 3's clock does not depend on it: it detects a late check on any platform. The reported `ms` is wall time on every platform.
- **The sleep also drains the time cap.** `end.ms` is summed per target (`src/drive.ts:623-624`) into `drive.caps.wallClockMs` (`src/caps.ts:53`), so a 9 h sleep charges 9 h of a 16 h cap.
- **P4.** `setTimeout(fn, 2147483648)` fires after 1 ms (`TimeoutOverflowWarning`). `drive.sessionTimeoutMs` has no upper bound (`src/settings.ts:178`, `INT1`), so any value ≥ 2³¹ ms stops every session at once. `realClock.sleep` already slices long waits for this reason (`src/usage.ts:13-24`).
- **The deadline stays a safe lower bound.** `WITNESS_DRIVE_DEADLINE` is `t0 + sessionTimeoutMs` in wall time (`src/drive.ts:200`). Only a reviewer's usage-limit wait inside a session reads it (`src/reviewer.ts:251`). A sleep can only push drive's stop later.

### E4 — #59 (read)

- **Only darwin holds the host awake.** `keepAwake` (`src/awake.ts:8-20`) holds `caffeinate -ims -w <pid>` on darwin and nothing elsewhere. On win32, drive prints `keep-awake: none on win32 — keep the host awake yourself` (`src/drive.ts:711-713`). It releases the hold while paused and takes it again afterwards (`:716-724`).
- **The PowerShell route already exists.** `src/notify.ts:32-38` already starts System32 Windows PowerShell 5.1 by absolute path, with its data in the environment. `resolveSpawn` (`src/spawn.ts:119`) and `treeStop` (`:166`) build their System32 paths inline.
- **Hiding follows the run mode.** The spawn wrapper hides children only under `--detach` (row 201). A foreground drive's children share its console.

## Calls made in this plan

- **C1. Two releases, fixes first.** This is the user's call (2026-10-28). This plan goes on branch `issues-58-60` and ships as 0.25.1. The calibration plan follows from `main` as 0.26.0.
- **C2. The delta floor counts only the files the change touched,** `min(5, k)`. Counting any changed file would let a delta lens prove reading without reading the change. Full rounds and the doc gates are unchanged.
- **C3. A repair carries verdicts only when the question is the same.** That means this run's full prompts hash equals the malformed run's `prompts_sha`, so a moved delta base runs the whole battery. `--fresh` keeps forcing the whole battery. Until 0.26.0, a re-asked lens walks today's model chain, so a repair can be a fallback round.
- **C4. The session clock ticks at most every 1 s on `performance.now()`.** A check more than 30 s late is sleep. Because no timer is armed for more than 1 s, P4 is fixed by construction. Residual: a drive event-loop stall over 30 s also reads as sleep.
- **C5. `drive.caps.wallClockMs` keeps its key and counts awake session time.** Renaming it would cost every consumer a `migrate` for a word.
- **C6. The Windows helper is a script, not a dependency.**
  - `Add-Type` P/Invokes `kernel32!SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED)`, then `Wait-Process` waits on drive's pid. No elevation, no `powercfg`.
  - On any platform, an early non-zero exit prints `keep-awake: lost`. A signal, exit 0, or win32's Ctrl+C status prints nothing.

**Interfaces:**
- Produces: `SESSION_TICK_MS = 1_000`, `SUSPEND_GAP_MS = 30_000`.
- Produces: `interface Ticker { now(): number; after(ms: number, fn: () => void): () => void }`, and `monotonicTicker: Ticker`, which is `performance.now()` with `setTimeout`/`clearTimeout`.
- Produces: `interface SessionClock { awakeMs(): number; stop(): void }`.
- Produces: `sessionClock(limitMs: number, ticker: Ticker, on: { expire(): void; slept(ms: number): void }): SessionClock`.
- Produces: `spawnSession`'s `opts` gains `ticker?: Ticker` (default `monotonicTicker`), and `SessionEnd.ms` becomes awake time.

The algorithm the signature leaves open:
- Record `t0 = ticker.now()`.
- Arm each check `wait = min(SESSION_TICK_MS, limitMs − awake)` ahead.
- When a check fires, compute `late = now − last − wait`. When `late > SUSPEND_GAP_MS`, add `late` to `asleep` and call `on.slept(late)`.
- Then `awake = now − t0 − asleep`. When `awake ≥ limitMs`, call `on.expire()` once and arm nothing more; otherwise arm the next check.
- `stop()` cancels the pending check and accounts the pending interval by the same rule, which catches a sleep no check has seen yet. It then freezes `awakeMs()`. After an expiry, `stop()` only freezes.

import { describe, expect, it } from 'vitest'
import { SESSION_TICK_MS, SUSPEND_GAP_MS, sessionClock, type Ticker } from '../src/session-clock.js'

// A host the test drives: `run` lets time pass awake, firing each check as it falls due; `sleep`
// moves the clock with nothing firing, as a suspended host does, so the next check fires late.
function host(): Ticker & { run(ms: number): void; sleep(ms: number): void; armed: number[] } {
  let now = 0
  const due: Array<{ at: number; fn: () => void; live: boolean }> = []
  const armed: number[] = []
  return {
    armed,
    now: () => now,
    after: (ms, fn) => { armed.push(ms); const t = { at: now + ms, fn, live: true }; due.push(t); return () => { t.live = false } },
    run(ms) {
      const end = now + ms
      for (;;) {
        const next = due.filter((t) => t.live && t.at <= end).sort((a, b) => a.at - b.at)[0]
        if (!next) break
        next.live = false
        now = Math.max(now, next.at)
        next.fn()
      }
      now = end
    },
    sleep(ms) { now += ms },
  }
}
const HOUR = 3_600_000
function clock(limit: number) {
  const h = host()
  const slept: number[] = []
  let expired = 0
  const c = sessionClock(limit, h, { expire: () => { expired += 1 }, slept: (ms) => slept.push(ms) })
  return { h, c, slept, expired: () => expired }
}
