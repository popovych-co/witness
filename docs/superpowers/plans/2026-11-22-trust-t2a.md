# witness trust T2a — Drive jobs and the queued test turn — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give drive a way to run machine work no session does — jobs, in time-boxed shards, journaled as bookkeeping, read by gates through one reading that says "not measured" when a result is missing outside drive — and make the test turn a FIFO queue a waiting session can be seen in, so a session waiting behind a job keeps its time; lint stops taking the turn.

**Architecture:** The turn (`src/runner-lock.ts`) gains leased tickets in `.witness/live/turn/`, taken in arrival order; the lock names a job holder. Drive hands each session a deadline file (`src/deadline.ts`) and stops counting session time while that session waits behind a job (`sessionClock`'s held intervals). Jobs are a registry of kinds (`src/jobs.ts`); drive (`src/drive-jobs.ts`) runs one shard at a time as a `witness job` child, time-boxes it from the child's own "running" line, and journals the outcome itself on the reserved `jobs` stream. No production kind exists yet: T2c's base lint is the first; a test-only fixture kind drives the suite.

**Tech Stack:** TypeScript (ESM, Node ≥ 20), vitest, the git CLI.

**Spec:** `docs/superpowers/specs/2026-11-21-trust-design.md` — §3.5 (DJ), §3.9 (locks and leases, as they touch the turn). The implementation map's T2a entry (`/Users/home/x/personal/witness/.superpowers/sdd/2026-11-21-trust/impl-map.md`, never committed) wins where it differs from the spec. This plan adds rows **255–257**, numbered in build order.

## Settled while planning (probed 2026-11-22, main 5594203)

The map left two questions open; reading the code and two probes settled six more.

1. **Time boxes and shard sizes.** No setting. Each job kind declares its own box (`boxMs(cfg)`) and shard count; T2c, T5 and T8 pick theirs and add settings to their train only if they need them. T2a takes no schema step.
2. **Where the deadline file lives.** `.witness/live/deadline/<drive pid>-<spawn n>.json` = `{"deadline": <epoch ms>}`, machine-local under the folder state commits exempt. Drive names it to every session in `WITNESS_DRIVE_DEADLINE_FILE` (an absolute path), writes it only once the session first waits behind a job, rewrites it as the wait grows, and removes it when the session ends. `WITNESS_DRIVE_DEADLINE` keeps its meaning (row 210: the earliest drive may stop the session). Readers take the later of the two: `busy.ts`'s bound (row 240) and the reviewer's usage-limit wait (F14).
3. **Who journals a shard: drive.** Probe `probes/t2a-group-kill.mjs` (beside the impl map): a SIGTERM to a detached child's process group ends it in 2 ms even while it is blocked in `execSync`, grandchildren included. A job child stopped at its box would die mid-write if it journaled. So the child prints its result and drive journals it in-process, as its settle pass already journals decisions. This amends row 145's "children journal their own acts" for jobs only; a killed drive still leaves nothing to clean up (the shard just runs again).
4. **How the child reports.** Its stdout carries one JSON object per line: `{"job":"running"}` when its work begins (after its turn), then `{"job":"result",…}` last. Probe (this session): on macOS, `process.stdout.write` of 70,001 bytes followed by `process.exit` delivered 65,536 bytes to a slow reader, and 60,001 of 60,001. So a result line is capped at **48 KiB** (`RESULT_MAX_BYTES = 49_152`); a bigger one reads `failed`.
5. **When the box starts.** At the child's `running` line, so time spent queued for the turn is never boxed. Under `drive.parallelSuites: true`, or for a kind that takes no turn, the line comes at once. The box counts awake time (`sessionClock`, row 210).
6. **Strikes.** A `timeout` or a `failed` shard is a strike. Two strikes on a shard read "not measured" and it never runs again for that key. The spec names timeouts only; a failure counts too, so a crashing job cannot loop drive. A shard a signal stopped (drive stopping, a lost lease) is no strike and journals nothing.
7. **Where results live.** The reserved `jobs` stream (repo-level keys such as base trees dominate T2c), one state commit per shard. fewhats, HYC and KYC hold no doc or stream named `jobs` (probed); wot is not on this machine (its rollout check).
8. **Lint takes no turn.** The only lint run today is ship's lint lane (`src/gates/ship.ts:121`). Lint boots no server or browser; cargo's own build-directory lock already serializes clippy with a test build (a reading, not probed).

**Designer calls.** Production registers no job kind in T2a: the fixture kind exists only under `WITNESS_FIXTURE_JOB`, a test-only seam on `WITNESS_DRIVE_AGENT_BIN`'s precedent, never documented. One job runs at a time, beside the sessions, in every drive (`--manual` and `--flow` included). Gated kinds run before ungated ones, and an ungated job's ticket yields to plan work. Time a session spends behind a job charges nothing to its target's wall-clock cap (as a host sleep, row 210). `drive.sessionTimeoutMs` keeps its comment (no re-comment, no schema step). UI 1a.5's run registry is not built, so there is no wiring here (whichever lands second wires it).

**Re-probed spec refs.** The deadline is set at `src/drive.ts:221` (spec: drive.ts:242); `busy.ts:225` and `reviewer.ts:280` read it; the turn is `src/runner-lock.ts`; `ENTRY_PROGRESS` is `src/progress.ts:10`; ship's lint lane is `src/gates/ship.ts:121` (spec: `ship.ts:87-88`).

**Upgrade effect.** None on gates, prompts or reviewed identities. Tickets appear under `.witness/live/turn/` (excluded like `live/busy`). An older CLI on the same machine takes the turn without queueing until the floor refuses it. `jobs` becomes a reserved id: a doc or effort with that id would become a canon error (none in the probed consumers).

## Review Focus

The input classes T2a's tests must not leave to chance, most likely first:

1. **A host that sleeps mid-job or mid-wait** (a laptop lid): neither a box nor a session's time counts the sleep; a sleep never becomes a timeout strike or held time. → Task 4, test 2 (held vs slept); Task 7, test 6 (a box across a sleep).
2. **A killed waiter whose pid Windows hands to another process**: its ticket stops counting once its lease lapses and never holds the queue past `TURN_LEASE_MS`. → Task 1, test 4.
3. **A session waiting behind another session's run, not a job's**: no held time, no moved deadline — today's limit stands. → Task 1, test 9; Task 4, test 4.
4. **`drive.parallelSuites: true`**: no ticket and no lock; a turn kind still starts its box (its `running` line comes at once). → Task 1, test 8; Task 6, test 2.
5. **A job child that dies without a result, or a drive stopped mid-job**: the first is one `failed` strike, the second journals nothing. → Task 7, tests 4–5.

**Interfaces:**
- Produces (`src/runner-lock.ts`):
  - `TURN_DIR = '.witness/live/turn'`, `TURN_LEASE_MS = 60_000`, `TURN_RENEW_MS = 10_000`
  - `interface TurnTicket { pid: number; since: number; until: number; session?: string; job?: string; gated?: boolean }`
  - `interface TurnHolder { pid: number; since?: number; job?: string }`
  - `interface TurnWho { job: string; gated: boolean }`
  - `turnHolder(root: string): TurnHolder | undefined` — the lock's holder while its pid lives; `since` and `job` only when well-typed (an older CLI's `{pid}` reads as `{ pid }`).
  - `turnTickets(root: string, now?: number): TurnTicket[]` — the live tickets, in `headTicket` order.
  - `headTicket(tickets: readonly TurnTicket[]): TurnTicket | undefined` — pure; the tickets are taken as live.
  - `sweepTurnQueue(root: string, now?: number): number` — stale tickets removed (count).
  - `behindJob(root: string, session: string, now?: number): string | undefined` — the holder's `job` while a live ticket carries `session`.
  - `withRunnerTurn<T>(runRoot: string, ctx: Ctx, label: string, fn: (env: Ctx['env']) => T, who?: TurnWho): T`
- Produces (`src/deadline.ts`): `DRIVE_DEADLINE_FILE_ENV = 'WITNESS_DRIVE_DEADLINE_FILE'`; `sessionToken(env: Record<string, string | undefined>): string | undefined` — the file's base name without `.json` when it matches `^[1-9][0-9]*-[1-9][0-9]*$`.

The rules the tests do not pin down:
- **Live ticket:** pid a positive integer and alive, `since ≤ now + 60_000`, `now ≤ until ≤ now + TURN_LEASE_MS + 60_000`. A link, a malformed file, or an unreadable file older than 1 s is stale.
- **Head order:** ascending `(yields, since, pid)`, where `yields` is 1 for a ticket with `job` and `gated === false` while any ticket without `job` is in the list.
- **A taker:** re-entry and an inherited turn first, unchanged and with no ticket; then `sweepTurnQueue`; then its ticket `<since>-<pid>.json` (`O_CREAT | O_EXCL | O_NOFOLLOW`, in a real folder — a link anywhere on the way is refused, as `busyDir` refuses one), carrying `session: sessionToken(ctx.env)` and `who`'s `job`/`gated`. Each pass: lock absent and its ticket at the head → `wx` the lock as `{pid, since: now, job?}`, remove its ticket, hold; a dead or unreadable holder → stolen as today; a live holder → said once, as today. A missing own ticket is written again with the same `since`; `until` is renewed every `TURN_RENEW_MS` (a temp file renamed over it). A queue folder that cannot be used → the turn is taken as before, unqueued.
- **Release:** the lock goes if it names this pid (unchanged), and the ticket again if it is still there.

The rules the tests do not pin down:
- **The child.** Spawned from `selfArgv(ctx.env.WITNESS_BIN, ['job', kind, key, '<k>/<n>'], env)` at the root, through `contained` on win32 (as a session), in its own process group elsewhere, with stdio `['ignore', 'pipe', 'pipe']`. Its group joins `LIVE_GROUPS`.
- **The box.** Started by the child's `running` line: `sessionClock(kind.boxMs(cfg), ticker, …)`; at expiry SIGTERM to the group, SIGKILL `TERM_GRACE_MS` later (`signalSession`). A late check prints `[job <kind>] host slept <duration> — not counted against its box`.
- **The outcome**, read when the child exits:

  | How it ended | Journaled | `ms` | Drive's line |
  |---|---|---|---|
  | a stop (signal, lost lease) | nothing | — | `job: <kind> <key> <k>/<n> — stopped` |
  | the box expired | `timeout`, `why: box <duration> passed` | box awake ms | `… — timed out · box <duration>` |
  | a valid result line | its outcome, `result` or `why` | box awake ms | `… — done · <duration>` / `… — failed · <why> · <duration>` |
  | no result line | `failed`, `why: exit <code or signal> without a result` | box awake ms, or 0 | `… — failed · <why>` |

  A result line is valid when it parses to the protocol's shape, is at most `RESULT_MAX_BYTES`, and its `why` is a string of at most 200 characters. A `journalShard` refusal prints its rows (`renderRefusal`) and the shard runs again later.
- **Drive's log.** `job: <kind> <key> <k>/<n> — started` at spawn; each stderr line of the child as `[job <kind>] <line>` through `logSafe`; stdout lines are read, never shown.
- **The loop.** After each round's fill, while no job runs and the run is not stopping: `job = startJob(…)`. Lanes empty and a job running → await its `end` (or the abort), then `continue`. Otherwise await the first of the lanes' ends and the job's `end`; a job's end clears `job`, sweeps and `continue`s. The abort stops the job (its `end` resolves after the child exits).
- **`launch`** passes `deadline: { root, token: '<drive pid>-<spawn n>', behind: () => behindJob(root, token) }`.
- **Sweeps** at drive's start and after every session and job: `releaseDeadTurn`, `sweepTurnQueue`, `sweepDeadBusy` (as today), `sweepDeadlines(root, <the running lanes' tokens>)`.
- **The report.** For each kind with shards journaled since the run began, in first-seen order: `jobs: <kind> <duration(sum of ms)> — <n> shard(s)` plus ` · <t> timed out` and ` · <f> failed` when non-zero, after the `decisions:` line.
