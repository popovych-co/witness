# witness trust T4a — A fix adds a check: guards — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A reviewer marks a blocking finding a machine could catch from now on (`guard: lint | test`). The author answers it with a check — a lint rule or a test — and proves it with `witness guard`: the check fails on the code the reviewer flagged and passes on the fix. The next round's `guards` check is a judged red for every marked finding without a proven guard, and the AI judge or the human may waive one.

**Architecture:** The verdict contract gains an optional per-finding `guard`, and the round that marks one pins its reviewed tree. `witness guard <plan> --finding <anchor> --files <path>… (--rule <tool>:<rule> | --test <name>…)` builds two trees — the marking round's reviewed tree with the guard's files folded over it (red), and the worktree's current tree (green), both with the base's `package.json` scripts — and runs each in the scratch: a lint guard reads the tool's diagnostics reader (the declared rule, at error severity, at the anchored file, and at a breadth copy of it with fresh local names and changed indentation), a test guard reads the named testcases from junit (run by file through a new `criteria.byFile` template, or the full suite). A proven guard is journaled on the plan's stream (`guard`, an act). A new judged check, `guards`, at implement and ship, reads every marked finding of the gate's rounds since its last reset; the judge's waiver is a decision, `--book guards`. The scratch lock first becomes held by a live pid, as the test turn is, so a session can share the scratch with drive's jobs across a host sleep.

**Tech Stack:** TypeScript (ESM, Node ≥ 20), vitest, the git CLI.

Each tree is pinned as `inScratch` pins any non-commit tree.

## Review Focus

The input classes T4a's tests must not leave to chance, most likely first:

1. **A host sleep while a job holds the scratch.** A waiting guard never takes the scratch over, and drive's sweep never frees its live child's lock. → Task 1, "a live holder past its old lease keeps the scratch".
2. **The environment empties a test run** (a service down: an empty report). The guard is refused `guard-not-run`: never proven, never a red. → Task 5, "a run that reports none of the named cases is the environment".
3. **A rule pinned to the anchor** — its path, a local's exact name, a regex on a name. It reads red on the round's tree and fails the breadth copy: `guard-too-narrow`. → Task 7.
