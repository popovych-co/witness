## Verified evidence base

### E1 — #21: the plan queue has no rung for a `live` spec (root cause, probed)

`computeNext` (`src/verbs/next.ts:498`) is an ordered first-match ladder. The plan-ready queue at **`next.ts:671-676`** filters `type === 'spec' && status === 'approved'`. But a spec goes `approved → live` when a plan of it merges (`src/stamp.ts:80`), and two paths return an amended spec to `live` *after* its decompose gate passed: `abandon`'s revert restores the prior committed status (`src/abandon.ts:37-66` — the reporter has `abandoned 1`, and `pi-engine` is amended by three of the five stuck efforts, so one abandon can evict three efforts), and the lazy post-merge stamp. The reporter's repo has **zero approved specs** (22 live, 1 draft) — `planless` is `[]` by arithmetic, every later rung is empty, and the ladder falls off the end into `return { line: 'witness check' }` (**`next.ts:716`**), byte-identical to the canon-error answer at `next.ts:508`, with no `note:` to tell them apart. `drive.ts:65` then classifies the whole loop idle.

`next` is the **only dissenter** on whether a live spec can parent a plan:

- `src/gates/plan.ts:37-40` — `parentOk = parentStatus === 'approved' || parentStatus === 'live'` (principles: `approved` only)
- `src/verbs/write.ts:277-280` — a plan write refuses only a `draft` parent
- `plugin/skills/witness-plan/SKILL.md:45` — "a spec accumulates plans over its life"
- `tests/write-plan.test.ts:15-27` — passing test: plan written against a `live` parent, exit 0

So witness *accepts* the exact command `next` refuses to *emit*.

**Why "admit live specs" alone is wrong:** efforts never auto-terminate (`liveEfforts`, `next.ts:209-214` — has recap ∧ not abandoned), and filter B already treats `done` plans as non-blocking. Unconditional admission would make every *finished* spec (live, all plans done, live effort) queue for a new plan forever. The distinguisher is the effort: the reporter's five efforts each passed decompose and own **zero plans** — that is the owed state. An effort whose plan shipped owns a `done` plan — nothing owed. The rung must be effort-keyed.

**Why the ladder supplies "decompose passed" for free:** rung 6 (`next.ts:597-640`) returns a decompose action for any live effort whose specs are not all non-draft or which has an open reopen. Reaching rung 8 therefore proves every live effort's decompose is settled — no journal read needed in the queue itself.

**Second latent defect, same rung:** the offered plan id is hardcoded `` `${spec}-plan-1` `` (`next.ts:681-683`). Already wrong today for an approved spec whose `plan-1` is `done` (the offer would amend a done plan); guaranteed wrong once live specs enter. The queue must offer the next free suffix.

**Adjacent, deliberately deferred (recorded in Task 5's residuals, not fixed here):**
- H2 — `ready()` (`next.ts:665-670`) counts a spec dependency ready only at `live`, so amending a live spec evicts all its dependents from the queue for the amendment's duration, invisibly (`dashboard.ts:26-31` skips live docs in `blocked`).
- H4 — the design rung (`next.ts:643`) has the same `approved`-only asymmetry; an amended ui spec re-enters design via the normal draft→approved path, so nothing reported hits it yet.

### E2 — #20: one git choke point, no `maxBuffer` (root cause, measured)

**Every git child-process call in `src/` routes through one function**: `git()` at **`src/gitio.ts:6-12`** — `execFileSync('git', args, { cwd, encoding: 'utf8', stdio: […] })`, no `maxBuffer` → Node default 1,048,576 bytes. `execFileSync` delegates to `spawnSync`, hence the reporter's exact message `spawnSync git ENOBUFS` (reproduced in-repo; `bin.ts:27-33` wraps it as `unexpected-error`, exit 2). The reporter measured a 1,282,479-byte `git diff origin/main`.

Overflow site on the ship path: **`src/gates/implement.ts:20`** — `codePromptBody` runs `git(wt, 'diff', base)` to build the reviewer prompt. Called from both `gates/ship.ts:104` and `gates/implement.ts:171`, so **`witness gate implement` has the identical bug**. The diff is genuinely needed whole — it is the LLM reviewer's input, and the downstream reviewer spawn already carries `maxBuffer: 64 MiB` (`reviewer.ts:134`); only the producer is unsized. The diff text is load-bearing nowhere else: gate evidence uses file names + lane exits, `diffReviewedSha` uses blob hashes (`reviewed.ts:26`), the PR body is a fixed one-liner (`ship.ts:88-90`).

**The worse half is silent:** `tryGit` (`gitio.ts:14-23`) swallows the throw and returns `{ ok: false, out: <truncated> }` — indistinguishable from "git failed". Consequences at >1 MiB of output: `dirtyStatePaths` (`gitio.ts:91`) returns `[]` and the `unrelated-dirty` guard vanishes; `stateOnlyAdvance` (`gitio.ts:59,70`) returns false and every ship run rebases + re-reviews needlessly; `materializedCanon` under-reports canon residue (`worktree.ts:106,115`). Raising the bound at the choke point fixes the crash class and the silent class in one line.

**Streaming rejected:** every consumer materializes the whole string anyway (prompt concatenation → `spawnSync` stdin), and an async `git()` ripples through every synchronous gate `resolve`. Precedent for sized-sync: `reviewer.ts:134` (64 MiB), `ship.ts:52-53` (`gh`, 16 MiB). gitio is the outlier. V8's ~512 MB string ceiling bounds what any in-process approach could do regardless; 256 MiB sits under it and above any diff a reviewer will ever be sent.

**Independent second bug, same ship path:** `execCommand` at **`src/runner.ts:58-66`** — `execSync(cmd, { stdio: 'pipe' })`, no `maxBuffer`. A test suite whose stdout exceeds 1 MiB throws ENOBUFS, lands in the catch, and is reported `exitZero: false` — **a green suite reads as a failed `tests` lane** (`gates/ship.ts:76`), blocking ship with a false red. The output is `.slice(-4000)`'d immediately, so a bounded 64 MiB buffer is the whole fix.

```ts
// The queue offered `<spec>-plan-1` unconditionally, which amends a DONE plan the moment
// a spec earns a second slice. Offer the first unused suffix instead.
function nextPlanId(plans: CanonDoc[], spec: string): string {
  const taken = plans
    .map((p) => String(p.meta.id))
    .filter((id) => id.startsWith(`${spec}-plan-`))
    .map((id) => Number(id.slice(`${spec}-plan-`.length)))
    .filter((n) => Number.isInteger(n) && n > 0)
  return `${spec}-plan-${taken.length > 0 ? Math.max(...taken) + 1 : 1}`
}
```

const GIT_MAX_BUFFER = 256 * 1024 * 1024

export function git(root: string, ...args: string[]): string {

  }).replace(/\n$/, '')
}
