# witness trust T2e — Ledger and bookings — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A human can book a lint red the author cannot fix — `witness decide <gate> <plan> --book lint` — so a checks-only round has a way on that is not a fix: the booking is one decision plus a ledger item on witness's own `ledger` stream, it waives exactly what it booked for that plan, the re-gate runs the lenses, the item closes once main no longer holds what was booked, a human may dismiss it at a terminal, a stop only the human may book reaches them as a decision naming the act, and no session can book, dismiss or keep a stop for itself.

**Architecture:** `src/ledger.ts` folds the reserved `ledger` stream into items (`open` → `closed` | `dismissed`). The lint lane reads the plan's open items: a part whose red is booked reads `booked` and passes, so `checksSignature` moves and the round runs fresh. `decide --book` is a fourth decision kind, live only on a checks-only round whose withheld check carries a waiver (`CHECKS`); it writes the decision and the items in one transaction under the repo lock, and leaves the gate in a new state, `booked`, whose one act is the re-gate. `recommend` gains rule `book-owed` for a lint red nobody but the human can clear; the policy leaves it to the human, and `needsYou` names its `--book` act. The merge stamp and the abandon close items in their own transactions from what the shipped tree's lint lane observed; `witness dismiss ledger` ends one at a terminal.

**Tech Stack:** TypeScript (ESM, Node ≥ 20), vitest, the git CLI.

**Spec:** `docs/superpowers/specs/2026-11-21-trust-design.md` — §3.2 (waiver, base-red), §3.3 (LD), §3.9 (two-stream acts; sessions cannot launder human acts), §5 (human-only waivers in needs-you). The implementation map's T2e entry (`/Users/home/x/personal/witness/.superpowers/sdd/2026-11-21-trust/impl-map.md`, never committed) wins where it differs from the spec. This plan takes T2d's hand-off (`t2d-progress.md`, "Hand-off (T2e)") and T2c's T2e notes (`t2c-progress.md`, "Hand-off"), settles the map's open question (point 11), and departs from the spec in seven places, recorded as corrections C17–C23. 2. **A booking** (§3.3, §3.2's waiver). `witness decide <gate> <plan> --book <check>` is a decision (`decision: 'book'`) on a checks-only round whose withheld check carries a waiver. `CHECKS` gains `waiver`: `lint` is `'human'`; markers, implement-gate, diff, evidence, regression, tests and drift-lane have none (T3 and T4a add the judge's). One `--book lint` books every bookable part of the round's lint check — each its own ledger item, all named in the one decision — and writes nothing else: no gate runs (the re-gate is routed). `--note` is optional and rides the decision and each item.
3. **What a part books, and how exactly.** Bookable: `red`, `new`, `not-measured`, `not-judged`. Never `pending` (drive is measuring the base: book after it lands), `untrusted` (a trust grant comes first), and never markers (no waiver). A part books **per diagnostic** when its verdict carries `book`, the multiset of keys a booking takes; otherwise **whole**. A whole-part booking holds at the part's base key (`<part>@<base commit>.<h12>` over the part's and reader's commands): it waives that part only while the plan is checked against the same base commit with the same commands — after a rebase onto newer main, or a command edit, the human is asked again (the user's call of 2026-11-24, "until main moves"; correction C19). A per-diagnostic booking holds wherever the booked keys are what is red.
4. **A reader-bound red part reads the plan's own diagnostics whatever its base (correction C20).** T2c reads the plan's tree only when the base is red and read (`new`, `base-only`). Now a red part with a bound, trusted reader reads it whenever its base is not `pending`: base green (`red`, all of the plan's diagnostics are new), base not measured (all of them, the base being unknown), base red but unreadable (`not-judged`, all of them). Its verdict gains `book` (≤ `MAX_BOOK_KEYS` = 500 distinct keys — past that, or with no reader, or when the plan's tree cannot be read, a part books whole), and a `red` part gains `new` and `rules` as `new` has them. A reader trust has not granted makes the part `untrusted`, as T2c's `new` path does (`trustOwed` owes it before any session anyway). So a whole-part booking is left only for parts witness cannot read.
5. **A booking waives its own plan, at both gates (correction C17).** The lint lane takes the plan's id and reads the plan's open items: a whole-part item whose `part_key` equals the part's key makes any non-passing state but `untrusted` read `booked`; per-diagnostic items on the part are summed into a multiset B, and the part's `book` multiset K loses B — nothing left (and K non-empty) reads `booked`, anything left keeps the part's state with only what is left as its `book`, `new` and `rules`. `booked` passes (`partPasses`), carries `booked` (diagnostics covered, or omitted for a whole part) and `items` (ids applied), and is a new term in `checksSignature`, so a booking made since a round always re-runs it fresh. An item of another plan, a closed or a dismissed item waives nothing. An item's identity therefore names its plan: §3.3's (kind, check, subject) with the plan in the subject.
6. **The gate after a booking.** A `book` decision is a disposition: `pendingDecision` sees a decision after the run (nothing owed), `gateSettled` and `gateParked` read false, `settlementTaken` ignores it, so `next` routes the gate (implement: `flowWork`'s `gate implement` row; ship: `witness ship`, whose phase reads `gate`), and drive routes the same. `liveActs` gains state `booked` — the latest disposition since the anchor is a `book` — whose one act is the re-gate. `--book <check>` is live on a checks-only anchor whose last check is the booked one, holds a bookable part, and carries a waiver, in the `pending`, `revised`, `handed-back` and `parked` states on unmoved content; never on moved content (the re-gate leads), at the bound (a checks-only round is never journaled there) or settled. Booking a parked gate lifts the park: a human's act, as row 241's revise is.
7. **Who may book** (§3.9). Refused for the policy and the arbiter (`autonomy-cannot`: lint's waiver is the human's, row 172), inside a session drive started (`book-human`), and on a nod (`nod-cannot`, D143: a booking opens a ledger item, as an override opens an obligation). Under committed autonomy (`autonomy: on`) a typed `--book` needs a terminal — `ctx.isTTY` plus a y/N prompt that lists each part and what it books (`book-needs-terminal`, `book-declined`); the env marker alone proves nothing. With autonomy off the chat's agent types it when the human names it (row 127).
8. **Recommend, the policy and the arbiter (correction C23).** §5 sends lint bookings to the human as decisions; the policy does so only where no author could clear the red. A new rule `book-owed`, before `checks-only`: the withheld check is lint and every part that does not pass is `not-judged` (red on the base too, and unjudgeable) — option 1 the booking (depth `deferral`, naming its discharge: the item closes once the part is green on main, or `witness dismiss ledger`), then the revise (fix the base's lint in this plan), the upstream where one resolves, the stop. The policy leaves `book-owed` to the human (`Policy` `{ kind: 'decision'; why }` → `Settled.left`, exit 1, no model call), so drive sets it aside as a decision and `needsYou` lists it. `checks-only` keeps the revise first (the author fixes what is theirs) and lists the booking after it when lint holds a bookable part; the policy still takes the revise (`TAKEN`). `menuFor` drops every `--book` of a check whose waiver is the human's. A part `not-measured` is the author's to look at first: it may be the plan's own red, and a machine cannot tell.
9. **The ledger** (§3.3). The reserved stream `ledger` (`reservedId`, `check`'s `RESERVED_STREAMS`; a writer refuses `stream-taken` when its first entry is not a `ledger-open`). Entries: `ledger-open` (an act: the booking's), `ledger-closed` (bookkeeping: an observation), `ledger-dismissed` (an act). Ids are minted (`l-` + 8 hex, as deferrals' `d-` are), and each open carries `key`, 16 hex over (kind, check, plan, part, subject — the part key for a whole part, the sorted keys for diagnostics): a booking whose key is already open reuses that item (the idempotence key). The fold reads the first end of an item and ignores any later one, and skips a malformed line.
10. **How an item closes (correction C18).** By observation, at two acts that already write a transaction: **the merge stamp** of plan M, from M's last ship gate-run that ran lint — the tree that merges — for every open item whose plan is M or has merged before (its stream holds a `status` to `done`, cause `merge`): a part `green` there ends every item on it; a per-diagnostic item the part's `cleared` lists ends; the close carries M, its PR and that run's `reviewed_tree`. **The abandon** of a plan closes that plan's open items (it never merges, so nothing it booked reaches main). Both compute their closes under the repo lock, inside the act's own transaction. `cleared` is the lint lane's observation, journaled on every part it read: the open per-diagnostic items on that part (any plan) whose every key the tree lacks. No base-lint job is owed for an item (C13 stands): main's debt closes when a later plan ships the part clean. An item whose part leaves the config is never observed again: `rule-retired` is its dismissal. A key the base held before the plan added the same line again keeps its item open until that line goes too — late, never early.
11. **Not owed work (correction C21; the map's open question).** Owed work is "open and not born" (§3.3), and only cleanups and repairs have a birth (T4b, T8b). A booked check has none: it closes by observation or dismissal, so `next` and drive never route one, and `status` lists them.
12. **Dismissal (correction C22).** `witness dismiss ledger --item <id|index> --cause <rule-retired|declined|judged-wrong> --note "<why>"` — row 122's verb with the reserved stream as its artifact; the index counts the open items as `status` lists them. Always at a terminal and never in a session (§3.3's "a human, at a terminal"): refused under any session marker (`dismiss-in-session`) and without `ctx.isTTY` (`dismiss-needs-terminal`), then a y/N prompt naming the item. `unknown-item`, `already-closed` (named apart: it is the good outcome), `already-dismissed`, `cause-required`, `note-required`. A dismissed item waives nothing from the next lint run on.
13. **`gate --manual` refuses inside a drive session** (§3.9): `manual-in-session`, before anything is read or journaled, `--unchanged --manual` too.
14. **What a human sees.** `status` prints `booked[n]{item,plan,part,holds,since}` rows (open items; `since` = the plan's gate and round, and `merged` once its plan has) and one `help:` line naming the dismissal; `witness log` names each transition; `decide --show` prints `state: booked — the re-gate reads the booking`; the lint detail names a booked part (`<part>: ok — booked: 3 diagnostics (l-1a2b3c4d)`, `<part>: ok — booked whole until main moves (l-1a2b3c4d)`); the arbiter reads `<part> booked by the human (3 diagnostics)` / `… booked whole by the human`.

## Review Focus

The input classes T2e's tests must not leave to chance, most likely first:

1. **The plan changes after a booking, adding another error to the booked part** — the per-diagnostic booking covers only what it booked: the re-gate is a checks-only round naming only the new error, never green. → Task 3, "a per-diagnostic booking covers exactly its keys".
2. **A rebase after a whole-part booking** — the part's base key moves, the booking no longer holds, and the human is asked again; a per-diagnostic booking still holds once the new base's result is read (with no drive, an unmeasured base's own errors count as bookable until it is). → Task 3, "a whole-part booking holds at the base it was booked against".
3. **Two parts red, one the author can fix** — the policy revises (the author fixes theirs); once only the base-red part is left the stop is `book-owed` and reaches the human; a `--book` typed before the fix books both parts, each listed. → Task 5, "two parts red, one the author can fix".

5. **A booking dismissed while its plan is in flight** — the next round's lint withholds again; the dismissal never reads as a pass. → Task 6, "ends an open item at a terminal".
