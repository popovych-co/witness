# witness trust T2b — Scratch runs and command trust — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give witness one persistent, provisioned scratch checkout per repo where machine work runs on trees other than a plan's worktree — locked and leased, reset between runs, prepared by a declared and trusted setup command, and honest about load failures — and make repo-level commands grantable once by the human, so a job whose command is untrusted waits for that grant instead of striking.

**Architecture:** CF is one synchronous call, `inScratch(root, ctx, cfg, at, step)` (`src/scratch.ts`): it resolves the tree (a commit as itself; a bare or overlaid tree wrapped in a deterministic commit and pinned under `refs/witness/cf/<plan>/<tree>`, `src/cf-tree.ts`), takes the leased scratch lock (`src/scratch-lock.ts`), resets `.witness/scratch`, runs `scratch.prepare` when a lockfile changed (`src/prepare.ts`), runs the caller's step, and re-prepares once on a load failure (`src/junit.ts` tells one from a red). It journals nothing: the record of every sha rides the caller's own entry. Trust gains a targetless grant for repo commands on the reserved `trust` stream; `migrate` grants its proposals in its own commit; a job kind declares its commands and whether it runs in the scratch, and drive checks them before a shard. No production job kind uses the scratch until T2c.

**Tech Stack:** TypeScript (ESM, Node ≥ 20), vitest, the git CLI.

**Spec:** `docs/superpowers/specs/2026-11-21-trust-design.md` — §3.4 (CF), §3.7 (trust), §3.9 (locks, leases), §6 (Train A). The implementation map's T2b entry (`/Users/home/x/personal/witness/.superpowers/sdd/2026-11-21-trust/impl-map.md`, never committed) wins where it differs from the spec; this plan settles its departures in its corrections C8–C11. ## Settled while planning (probed 2026-11-22/23, branch trust-t2 at aff0d06)

The map's T2b entry named three probes and no open question; the probes and the code raised eleven. Probe files sit beside the impl map in `probes/` (never committed).

1. **Where the scratch lives: `.witness/scratch`.** Inside the primary root (short, fixed, gone with the repo): a git worktree, detached at whatever it runs, with a plan worktree's sparse patterns (row 132: canon hidden, the payload home kept). Probe (`t2b-prepare.log`): in fewhats, ESLint at a checkout root ignores files under `.witness/` (its `files` globs are rooted: "no matching configuration"), Biome excludes `!.witness` in both consumers, and both vitest configs include rooted globs only — a root-level `pnpm lint` or `pnpm test` never walks into the scratch. `ensureExcluded` adds `.witness/scratch/`; `dirtyStatePaths` exempts it.
2. **Trees.** A commit runs as itself. A bare tree (an overlay's fold now, a pinned reviewed tree in T4a) is wrapped by `git commit-tree --no-gpg-sign` with a fixed identity and date (`witness <witness@local>`, `@0 +0000`), so one tree always wraps to one commit, and pinned at `refs/witness/cf/<plan>/<tree>` until the merge stamp drops the plan's refs. Per (plan, tree), not per round: nothing finds, keeps or drops a ref by its round. Probe `t2b-cf-git.sh`: a pinned tree survives `gc --prune=now`; reset (`checkout --force --detach` + `clean -ffdx -e node_modules -e target`) keeps `node_modules` and `target` at any depth; the scratch's HEAD reflog kept a wrapped commit alive after its ref went, so the scratch turns its reflog off.
3. **Prepare's inputs are a built-in list, not a setting:** tracked files at any depth whose base name is a lockfile or a package manager's own config (`PREPARE_INPUTS`; wot holds five `Cargo.lock`). A manifest's dependency edit moves its lockfile (`--frozen-lockfile` refuses otherwise), so `package.json` is left out: a scripts-only edit needs no reinstall. An input the list misses is caught by the load rule (point 5). Probe: a fresh prepare in a fewhats scratch took 6.2 s with a warm pnpm store, a no-op 0.85 s; `node_modules` is APFS clones of the store.
4. **The prepare record** is `witness-prepare.json` (`{cmd, inputs}`) in the scratch's own git dir: it lives and dies with the scratch, survives reset and clean, is removed before prepare starts and written after exit 0 — so a prepare killed mid-way (drive stopping a job at its box) leaves no record, and the next run prepares again.
5. **A load failure is not `<error>` alone.** Probe `t2b-junit-vitest-4.1.10.xml`: vitest 4.1.10 (both consumers) never writes `<error>`. A missing import, a syntax error, a module that throws at import and a `beforeAll` that throws each write `<failure>` on a synthetic testcase whose `name` equals its `classname` (the file); an assertion or a `TypeError` in a test writes `<failure>` on that test. So a load failure is a testcase holding `<error>`, or a failed one named exactly as its classname. `parseJUnit` marks it `load: true` and its status stays `failed`, so no existing reader changes. In a scratch run any load failure re-prepares once and runs again; a second is the environment (`load-failure`), never a red.
6. **CF is `inScratch(root, ctx, cfg, at, step)`, synchronous, with no command string.** The caller's `step(dir)` runs what it runs in the prepared checkout (a lint part, a suite and its report) and returns its value with its load failures; CF returns that value with a record of every sha (`base`, `overlay`, `tree`, `commit`, the prepare inputs). CF journals nothing and keeps no cache: a job child must never journal (row 257), so the record rides the caller's result, and each caller's journal is its cache (a job by its key, T4a's guard by its entry). Synchronous because nothing in it may prompt — CF is headless — and because `withRunnerTurn` releases in a `finally` an async step would outrun.
7. **The scratch lock** is `.witness/live/scratch/lock.json` = `{pid, since, until}` (busy.ts's shape), taken `O_CREAT | O_EXCL | O_NOFOLLOW` in a folder that is no link, re-entered by its own pid, waited for while its holder lives and its lease holds (the turn's rule: never refused for busy), and taken over once its pid is dead or its `until` passed. The lease is written once, at the take: the job verb writes its box plus `TERM_GRACE_MS` plus 10 min; other callers `drive.sessionTimeoutMs`. Drive's `sweep` releases a dead holder's lock, as it does the turn's (row 218), before Windows can hand its pid on. Lock order is turn → scratch → repo lock, and `takeTurn` throws when its own process holds the scratch: a step that took the turn inside the scratch could deadlock against a session holding the turn and waiting for the scratch.
8. **Jobs.** `JobKind` gains `scratch` (its shards run in the scratch) and `commands(cfg)` (the repo commands its shards run). The job verb takes the scratch after the turn and before its `running` line, so a wait for the scratch is never boxed (T2a's rule for the turn); reset and prepare run inside the box, so a scratch kind's box must hold one prepare and one re-prepare (T2c sizes its own).
9. **Trust.** The user delegated both open calls ("what is not a band aid"):
   - **Prepare pins nothing (correction C9).** A pin earns its stop only where a command runs with access the agents lack — explore's login reads real secrets. Prepare runs as the user every session runs as, and those sessions already run `pnpm install`. Pinning manifests and lockfiles would ask again after 11 of fewhats' 22 merges and 14 of wot's 16 (`t2b-merges.sh`), which trains a human to approve without reading. Pins land in T8 with the explore host and login, carrying the map's acceptance "a changed blob-pinned file raises the trust item again".
   - **Typed tokens, `expect` and the "green on current" reuse land with their first users (correction C10):** tokens with the first command that appends one (T2c's readers or T4a's guards), `expect` and the reuse with T4a's guards — each designed against a real command, Windows quoting included.
   - **Repo commands get a grant with no target:** `witness trust --cmd '<exact>'` for the runner, `ship.test`, `ship.lint` and `scratch.prepare`, journaled on the reserved `trust` stream. A job serves no artifact, so its trust wait names this grant.
   - **`migrate` at a terminal asks once per command it proposes, before it writes,** and each yes rides the same transaction and commit as the config.
   - **A job kind whose commands are untrusted is skipped, never struck,** and drive sets aside one `jobs` trust wait that needs-you, the report, the notifier and `witness wait` name with the targetless grant.
10. **Settings: `scratch.prepare` only, in schema 3** — Train A's one schema step; T2c adds its settings to schema 3 and re-pins its fingerprint, since nothing releases between. Shape text, `ambient`, group setup, default `none`. An older file reads it absent, which turns scratch runs off (`check` says so, once). `init` and `migrate` write what the root's lockfile names (`detectPrepare`).
11. **No new journal kind.** A targetless grant is a `trust` entry (an act, as today); CF runs ride their caller's entries (a `job-shard` is bookkeeping).

  it('a vitest file that failed outside any test is a load failure; a failed test is a red', () => {
    expect(parseJUnit(VITEST)).toEqual([
      { name: 'assertion fails', classname: 'a-assert.test.ts', status: 'failed' },
      { name: 'passes', classname: 'a-assert.test.ts', status: 'passed' },

- **The lock:** the folder through `liveFolder(root, 'scratch', true)` — a link on the way, or a folder that cannot be made, refuses `scratch-unusable` (field `.witness/live/scratch`). The file is created `O_CREAT | O_EXCL | O_NOFOLLOW` as `{pid, since: now, until: now + leaseMs}`; a scanner's transient `EPERM`, `EBUSY` or `EACCES` is retried within 1 s (busy.ts's rule). The file naming this pid: `fn` runs at once and nothing is released. A live holder: `scratch: waiting for pid <n>` once on stderr, a poll every 200 ms, never a refusal. A dead holder, a lapsed lease, a malformed file, a link at the file, or a file unreadable past 1 s: taken through `takeStale` (`src/lock.ts`). Release (in a `finally`): the file is removed only while it still holds what this taker wrote.
- **The place:** `lstat` the path — a link or a non-directory refuses `scratch-unusable` (want `remove .witness/scratch — witness makes it again`). An existing folder must be a worktree of this repository (its `rev-parse --show-toplevel` is the path by realpath, and its absolute `--git-common-dir` is the root's), else the same refusal. **Interfaces:**
- Consumes: `objectType`, `foldOverlay`, `pinTree` (Task 3); `withScratch` (Task 4); `openScratch`, `resetScratch` (Task 4); `prepareScratch`, `prepareInputs` (Task 5); `loadFailures` (Task 1).
- Produces (`src/scratch.ts`):
  - `interface CfAt { tree: string; overlay?: CfOverlay; plan?: string }` — `tree` a full commit or tree sha; `plan` pins a run whose tree is no commit.
  - `interface CfRecord { base: string; overlay?: { from: string; paths: string[] }; tree: string; commit: string; inputs: string; prepared: boolean; reprepared: boolean; ms: number }` — `base` the tree `at.tree` names; `overlay.from` the tree `at.overlay.from` names; `tree` the tree run; `commit` the commit checked out; `inputs` `prepareInputs(tree)`; `prepared` whether the run's first prepare ran (its inputs moved, or no record); `reprepared` whether the load rule ran a second one.
  - `interface CfStep<T> { value: T; load: string[] }`
  - `inScratch<T>(root: string, ctx: Ctx, cfg: Config, at: CfAt, step: (dir: string) => Result<CfStep<T>>, opts?: { leaseMs?: number }): Result<{ value: T; record: CfRecord }>` — `leaseMs` defaults to `cfg.drive.sessionTimeoutMs`.

In order:
1. `cfg.scratch.prepare === undefined` → `scratch-off`.
2. `objectType(root, at.tree)` undefined → `tree-unknown`.
3. `base` = the tree; with an overlay, `tree = foldOverlay(root, base, at.overlay)`, else `tree = base`.
4. `commit` = `at.tree` when it is a commit and there is no overlay; otherwise `pinTree(root, at.plan, tree)` — no `at.plan` refuses `cf-unpinned` (want `the plan whose run pins this tree — refs/witness/cf/<plan>/ keep it until the plan merges`).
5. Inside `withScratch(root, ctx, leaseMs, …)`: `openScratch`, `resetScratch(dir, commit)`, `prepareScratch(… tree)`, `step(dir)`. A refused step is returned as it is. A step with load failures: `prepareScratch(…, { force: true })`, `resetScratch(dir, commit)`, `step(dir)` once more; load failures again → refuse `load-failure` (field `scratch`, got the files joined ` · ` through `visible()`, want `a run whose files load — prepared again once; this is the environment, never a red`).
6. `ms` is the call's wall time.

The step's contract, in `inScratch`'s header comment: it runs its commands with `execCommand(dir, ctx, cmd, { turn: false })`; a run that needs the test turn takes it before `inScratch` (Task 4's throw); it returns its junit's `loadFailures`, or `[]` when it reads no junit.
