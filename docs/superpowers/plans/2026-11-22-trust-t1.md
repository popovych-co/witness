> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the human a measured baseline before any trust check lands — `record(repo)`: escapes per shipped plan (from each fix effort's confirmed cause, charged approximately), live specs failing (debounced, apart from "could not verify"), and "not measured" for the folds later items fill — shown in `witness status` and drive's report; and start journaling the four facts later items read (check durations, the evidence tree and each capture's producing test, drift testcase outcomes, ship's junit summary).

The journal gains are additive fields written where the facts are already in hand; the ship gate runs its suite once and journals that run's junit summary.

**Tech Stack:** TypeScript (ESM, Node ≥ 20), vitest, the git CLI.

## Settled while planning (probed 2026-11-22, main f5587b4)

The map left three questions open; the probes also turned up four facts the spec does not state.

1. **How old fixes get a cause.** fewhats has 3 fix efforts, HYC 5, KYC 12 live (1 abandoned), wot 0 — none carries a cause. A fix that predates causes is classified with `witness recap --effort <slug> --cause escape|decision`, which status names for every fix still lacking one. The values are the human's; the acceptance check on fewhats runs after the rollout.
2. **Why a cause is its own entry, not a recap field.** `effortReviewedSha` hashes the whole latest recap (`src/reviewed.ts:176`), the arbiter reads the recap (`src/arbiter.ts:208`), and an amendment re-arms decompose (row 52). A cause set later through `recap --amend` would move the decompose identity and re-open finished efforts, and a cause inside the recap reaches a reviewer. The recap *file* carries `cause` (the grill confirms it in the playback); the verb journals it as a `cause` entry beside the recap.
3. **The debounce.** A testcase counts as failing when it failed in each of its spec's last two drift runs that carry outcomes. A red with no named failing testcase — 0 tagged, every tagged case skipped, a failing `cmd`, a suite that did not run — is "could not verify". fewhats: 32 red drift runs, 31 of them those shapes; the one named red (signin-email-code `r-dbcdb643`, 2 failed) passed on the next run, so 0 failing.
4. **How a capture names its producing test.** A sidecar `<name>.png.json` = `{"test": "<full test name>"}`. Both harnesses run under vitest (fewhats `apps/web/e2e/support/harness.ts:1786` `capture`, wot `apps/client/test/harness/screens.ts` `captureScreen`/`captureWindow`), and the junit testcase name is the describe chain joined by ` > ` plus the test name — exactly `expect.getState().currentTestName` (fewhats' `reports/junit.xml` carries 261 such names). T6 owns the fallback when a capture has none.
5. **Order without timestamps.** Every merge stamp (`merge(<plan>): pr #N`, `src/stamp.ts:129`) and every recap birth (`recap(<slug>): <class>`, `src/verbs/recap.ts`) is a state commit with the `Witness-State: 1` trailer — 40 in fewhats, 80 in KYC, 28 in HYC, 24 in wot, all trailered. One `git log` over them takes 33 ms on fewhats' 1,860 commits; blaming every journal stream took 5.5 s. KYC holds 3 duplicate merge subjects: the first wins.
6. **The charging rule, run on real data** (prototype and output: `probes/t1-charge.mjs`, `probes/t1-charge.log` beside the impl map; the journal survey: `probes/t1-journals.mjs`, `.log`): fewhats single-use-code-race → signin-email-code-plan-1 (age 0), browser-exposure-posture → instagram-channel-plan-1 (age 6), pairing-code-attempts → uncharged (laptop-pairing had shipped nothing before it); HYC 5 of 5 charged (ages 0–16); KYC 12 of 12 live fixes charged, 5 shipped plans with no ship gate-run (version unknown); wot has no fix effort.
7. **Ship ran its suite twice in full-suite mode**: the tests lane (`commandLane`, `src/gates/ship.ts:97`) and the criteria lane again (`runCriteria`, `src/criteria.ts:59`). No row asks for it; only the config comment notes it. T1 runs it once and the criteria lane reads that run, so "ship's junit summary" names one run. (Row 252.)

**Designer calls.** Live specs failing is the current state per live spec (the fold's name); escapes are cumulative, grouped by version (the baseline T2–T8 compare against). Escapes read "not measured" until one fix effort carries a cause — zero fix efforts is no measurement. No new setting, so no schema step. Filtered-runner repos journal no drift outcomes and no ship summary (residual, row 251).

**Upgrade effect.** None on gates: checks compare on `ok`, `untrusted` and `held` only (`src/gate.ts:641`), the new fields are additive, and no prompt or identity changes. Consumers see a `record:` line; a fix recap now needs a cause (the skills bump with the CLI).

## Global Constraints

- Every new journal kind gets an `ENTRY_PROGRESS` row (`src/progress.ts`): `cause` is **bookkeeping**.
- Missing data reads "not measured"; nothing reads green by absence. The record never feeds a gate or autonomy: no gate, arbiter, recommend, autonomy, settle, next or decide path reads `record()` or a cause (Task 10's guard test).
- The record prints only ids, counts and CLI versions, through `kv`/`rows` (`src/toon.ts`). Testcase names and capture test names are journaled, never printed by T1.
- Journal keys are snake_case (`duration_ms`); models are camelCase TypeScript.
- Commands witness runs are declared and trusted as today; T1 runs no new command.

## Review Focus

The input classes T1's tests must not leave to chance, most likely first:

1. **History without witness's state-commit subjects** (squashed, rewritten, hand-made merges): an escape reads uncharged "order unknown" — never charged to a wrong plan — and the denominators still count every shipped plan. → Task 8, test 9.
2. **Drift runs that could not run the tests** (an untrusted suite, no reports, every tagged case skipped, 0 tagged, a failing `cmd`): "could not verify", never failing and never passing. → Task 9, test 3.
3. **A capture sidecar that is malformed, multi-line or oversized**: the capture stays witnessed, its test is dropped, one warning names it. → Task 4, test 4.
4. **A fix effort amended to another class, abandoned, or classified twice**: only a live effort whose latest class is `fix` counts; the latest cause wins. → Task 5, tests 5–6; Task 8, test 7.
5. **A ship suite that is untrusted or interrupted**: the tests check fails as before, no summary is journaled, and the criteria lane says why as before. → Task 2, test 4.

**The algorithm** (decisions the tests pin):
1. Read each effort stream once. A *live fix effort* is one whose latest recap class is `fix` and that is not abandoned; its cause is `effortCause` of its stream.
2. A plan's *maker* is the effort whose `write` of it has `created: true`; with none, `effortOf(root, id)`. A plan is *made by a chore* when its maker's latest recap class is `chore`.
3. A plan is *shipped* when its stream holds a `status` entry with cause `merge`. `plans` counts shipped plans not made by a chore.
4. A shipped plan's *version* is the `w` of the last `gate-run` with gate `ship` on its stream when it matches `/^\d+\.\d+\.\d+[0-9A-Za-z.+-]{0,24}$/`; otherwise `unknown`.
5. For each escape: *candidates* are shipped plans not made by a chore whose `meta.parent` is an artifact the fix's `write` entries name. The clock is read once, and only when an escape exists. No clock, or no birth for the fix → `order-unknown`. Of the candidates with a merge position before the birth, the latest is charged: `{ plan, version, age: mergesBetween(clock, itsPosition, birth) }`. None before it → `order-unknown` when a candidate has no position, else `nothing-shipped-before`.
6. Decisions are never charged. `byVersion` groups `plans` by version and counts escapes by the charged plan's version, sorted by version number descending (numeric segment compare), `unknown` last.
