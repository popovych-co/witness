## Decisions this plan settles (the map's open questions)

1. **The hooks' home is `.witness/hooks/`.** fewhats and wot both list `"!.witness"` and `"!.pi"` in Biome's `files.includes` (read 2026-11-22). Their ESLint configs restrict `files` to `apps/**/src/**` and `packages/**/src/**`, so ESLint applies no rule to a hook. `.witness` stays a state dir and `stateDirs()` is unchanged, so journaled `canonDirs` stay byte-identical. `.witness/hooks/` is carved out in one place:
   - `isStatePath` is false for it, so `stateCommit` refuses it as `out-of-scope`.
   - `dirtyStatePaths` and `materializedCanon` skip it.
   - `canonPatterns` re-includes it.

   The carve-out filters in JS, never with `:(exclude)` pathspec magic, which `GIT_LITERAL_PATHSPECS=1` turns literal (T0a's slice-1 minor). `canon-guard.mjs` guards only specs, plans and designs, so it needs no change.
2. **The old home retires: at the root at once, in a worktree when ship carries it.** A worktree's `.claude/settings.json` is its branch's, and init never writes it, since that would make it a plan change. So a worktree started before the upgrade still runs `.claude/hooks/*`, and init leaves those files there, frozen. Removing them at init loses that worktree's guard, and the probe's F/A shape shows the removal commit can also stop ship's rebase with a directory-rename conflict. At the root, init rewires the settings and removes the three old files in its own commit. On a plan branch, the ship gate drops each retired file the plan's base lacks, in a commit, before its lanes run. That is the moment the rebase has brought the base's new settings and hooks. The probe's F/S shape is exactly what it cleans. B shapes need nothing.
3. **Old-pattern worktrees get new patterns before anything lands in `.witness/hooks/`.** On the old patterns, init's `git add` refuses and its `commit --only` throws, and a rebase leaves the hooks skip-worktree, with the guard missing on disk (`t0b-sparse.sh`). `refreshSparse` rewrites a worktree's patterns when they differ and re-reads the tree. Init runs it in every worktree before syncing, and the ship gate runs it before dropping retired files. It never refuses: residue stays the business of `start` and `check`.
4. **Settings are rewired in place, kept to one set and written in the formatter's style.** Only two command strings ever shipped (read from all 11 versions of `src/install.ts`), and exactly those are rewritten. A hand-edited variant is the human's. The writer reproduces Biome's default JSON style, which Prettier's matches: objects one key per line, and an all-scalar array on one line when the whole line fits.
   - Style precedence: the root Biome config's JSON indent and width, then Biome's own default (tab) when the config sets none and extends nothing, then the file's own indent, then 2 spaces. The width is 80 unless the config sets one.
   - The fewhats golden is generated by fewhats' own Biome (Task 4), never typed by hand.
5. **`payload-linted` reads Biome's config only.** The rule is the probed truth table:
   - The local `files.includes` decides by its last matching pattern; a pattern naming a directory covers what is under it.
   - Where no local pattern matches, an `extends` list decides, assumed to include everything (presets such as ultracite start with `"**"`). With no `extends`, an unmatched path is not checked.
   - No `includes` at all: everything is checked.
   - A path is checked unless the formatter, the linter and the assist are all off for it (`biome check` runs all three).

   ESLint flat configs are code and cannot be read statically, so ESLint, Prettier and other tools are left to T2c's readers (Open entry).
6. **#94: only `gh pr create` sends text today.** `pr list`, `pr view`, `pr checks` and `pr merge` send none, and needs-you prints `gh` lines for a human. The title stays an argument: an id plus a summary capped at 120 characters (`src/schemas.ts:52`). CI is ubuntu-only, so the suite proves the argv/stdin split, and the Windows run is a human check, as rows 201 and 223 were.
7. **Renames.** `--no-renames` goes in `planChangeSet` (`src/change-set.ts:36`) and in `stateOnlyAdvance` (`src/gitio.ts:123`). Without it, a trailered commit that moves a source file into a state dir reads as bookkeeping. The prompt diff (`src/gates/implement.ts:27`) keeps git's rename view, whose header names both paths. Every other `--name-only` caller already passes `--no-renames`, or follows renames on purpose (`adopt`'s `log --follow`), or cannot see a rename (`ls-tree`; sync's unmerged list).
8. **Upgrade effects** (probed read-only, 2026-11-22):
   - The hook move changes no reviewed identity, because both homes are in `witnessPaths()`.
   - A settled gate whose diff holds a rename lapses once (row 96's precedent). fewhats' two in-flight plans hold no rename. wot's worktrees live on the Windows machine, unprobed.
   - init's root commit is real base movement, as every payload upgrade's is. So a plan past its ship gate re-gates once at its next ship. fewhats' two plans are before ship (T0a decision 8).
   - fewhats' two worktrees are the F shape: they run their frozen hooks until their ships drop them.
   - HYC and KYC have no plan in progress. wot runs pi, whose payload does not move.

**Interfaces:**
- Produces (`src/json-format.ts`):
  - `interface JsonStyle { indent: string; lineWidth: number; tabWidth: number }`.
  - `DEFAULT_JSON_STYLE: JsonStyle = { indent: '  ', lineWidth: 80, tabWidth: 2 }`.
  - `formatJson(value: unknown, style: JsonStyle = DEFAULT_JSON_STYLE): string`, ending in `\n`. The rule:
    - An object prints one key per line; `{}` and `[]` print as such.
    - An array whose every element is a string, number, boolean or null prints on one line as `[a, b]` when the whole line fits in `lineWidth` columns. The line is its indentation (a tab counts `tabWidth`), the `"key": ` prefix, the array and a trailing comma when one follows.
    - Any other array prints one element per line. Scalars print as `JSON.stringify` does.
- Produces (`src/lint-config.ts`):
  - `parseJsonc(text: string): unknown`. It strips `//` and `/* */` comments outside strings and a comma before `}` or `]`, then `JSON.parse`. It throws on invalid input.
  - `readBiomeConfig(root: string): { file: string; doc: Record<string, unknown> } | undefined`. It reads `biome.json`, then `biome.jsonc`, at the root. Missing, unparseable or not an object gives `undefined`.
  - `jsonStyle(root: string, existing: string | undefined): JsonStyle`, by decision 4:
    1. The indent is the config's `json.formatter.indentStyle`, else `formatter.indentStyle` (`'tab'` → `'\t'`, `'space'` → that many spaces). The count is `json.formatter.indentWidth`, else `formatter.indentWidth`, else 2.
    2. With neither set: a config with no `extends` gives `'\t'`, Biome's default. Otherwise, or with no config, the indent is the leading whitespace of the first indented line of `existing` (`'\t'` if it holds a tab, else that many spaces), else `'  '`.
    3. `lineWidth` is `json.formatter.lineWidth`, else `formatter.lineWidth`, else 80. `tabWidth` is the resolved indent width, else 2.
- Produces (`src/install.ts`):
  - `mergeSettings(existing: string | undefined, style: JsonStyle = DEFAULT_JSON_STYLE): { text: string; changed: boolean }`. An unparseable file still returns unchanged. Otherwise, in order:
    1. In every array under `hooks`, each `hooks[].command` equal to a retired command becomes its successor, in place.
    2. Within each array, an entry whose `hooks` is exactly one witness command is dropped when an earlier entry has the same `matcher` and that same single command.
    3. The appends run as today.
    4. `changed` is true when any of 1–3 changed the document. `text` is `formatJson(doc, style)`.
  - `namesRetired(text: string): boolean` is true when `text` contains a retired command as a JSON string literal (`JSON.stringify(cmd)`).

  - `undefined` when there is no readable Biome config, or none of `paths` is one Biome checks. Only these extensions count: `.js .mjs .cjs .jsx .ts .mts .cts .tsx .json .jsonc .css .graphql .gql`.
  - `config` is the config's file name. `paths` are the checked ones, sorted. `dirs` are their distinct first segments (`.witness`, `.pi`).
  - The decision for one path, per decision 5:
    1. **Patterns.** Strip a leading `!!` or `!` (it marks an exclusion), then `./` and `/`. Convert to a regex anchored at both ends: `**/` matches any directories, a trailing `/**` matches anything under, `**` alone matches anything, `*` matches within one segment, `?` matches one character, and everything else is literal. A pattern matches a path when it matches the path or one of its parent directories.
    2. **Files.** `includes` is the local `files.includes`, followed by each Biome 1.x `files.ignore` entry as an exclusion. With no `includes`, the path is kept. Otherwise the last matching pattern decides. When none matches, the path is kept only if the config has a non-empty `extends`.

    4. The path is checked when its files decision keeps it and at least one tool is on.
