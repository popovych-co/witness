# witness trust T3b — Tests a plan loses, and booking them — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A plan whose passing tagged tests fall below its base's — a case skipped (`{ skip: true }`, `it['skip'](`, `it.todo(`, `it.skipIf(true)(`), removed, untagged or excluded — is a judged red in the `switch-offs` check at implement and ship, booked by the AI judge or the human like a switch-off line, and a booked loss closes once main has the cases back. The base's counts come from a shipped summary of the same code, else from a drive job that runs the base's suite.

**Architecture:** Every full-suite ship summary now names its code tree (the tree with witness's state, canon and payload taken out) and its suite. The base's per-spec counts are any shipped summary or `base-tests` job result for the base commit's code tree. `src/tests-effect.ts` compares those counts with the round's own suite run (the criteria lane's at implement, the tests lane's at ship), spec by spec: new skips always count, and passing cases lost beyond new failures and skips count unless the plan's own parent spec was amended since its previous plan. The `switch-offs` check (now last in the registry) journals each loss as a `dropped` hit beside its token lines. With no base counts it reads "not checked" and owes the job. The ledger gains a third kind, `booked-dropped`, booked through T3a's `--book switch-offs` and closed at the merge stamp from the shipped summary.

**Tech Stack:** TypeScript (ESM, Node ≥ 20), vitest, the git CLI.

**Spec:** `docs/superpowers/specs/2026-11-21-trust-design.md`. The sections it implements:
- §4 T3, the effect layer's tests half: "passing tagged cases per @spec never drop without a spec amendment. The base comes from ship's persisted junit summary when the trees match; otherwise a DJ job runs it", and the acceptance "`{skip: true}` drops the passing count and is caught".
- §3.5: "T3's test half: 'not checked' for that round".
- §3.3 (the ledger gains a third kind), §3.2 (the judge's waiver), §3.9 (the arbiter reads facts only).

2. **"When the trees match" means the code trees (correction C29).** Every journal line and every stamp is a commit on main, so main's whole tree moves without any code moving.

   - The base's counts are the newest shipped summary, on any stream, whose `code` and `suite` match the base commit's. Failing that, they are a `base-tests` result with the same code and suite on the `jobs` stream; one such result serves every base commit with that code.

3. **What counts as lost (correction C30).** The summary keeps counts, never test names (row 251), and a spec's count is net. Per spec `S` the base holds, the counts compare against the round's own outcomes: `matchesTag` for each base spec id, so a spec the plan never tags reads zero.
   - `s` = the plan's skipped cases − the base's, at least 0. **New skips always count.** `{ skip: true }`, `it['skip'](`, `it.todo(` and `it.skipIf(true)(` all reach the junit report as `<skipped/>` (`t3b-vitest-skip.log`), so this catches every spelling the token layer misses.
   - `f` = the plan's failed cases − the base's, at least 0. A new failure is the tests lane's red, never a loss.
   - `lost` = (the base's passed cases − the plan's) − `f` − `s`, at least 0: cases removed, untagged, renamed away or excluded by config.
   - The spec's count is `s` + `lost`, or `s` alone under the license (point 4).
   - Additions net out. A plan that adds two cases and removes one reads no loss (recorded in Open), but one that adds cases and skips an old one still reads its skip (Review Focus 1).
   - A base spec that is no longer in canon (renamed, abandoned) is not compared.
4. **The amendment license (correction C31).** "Without a spec amendment" is read through witness's one derivation of a spec's delta (row 160, `baseForSpec` in `src/history.ts`).
   - The plan's own parent spec is licensed when no other plan of it exists, or when the newest one's pin differs from this plan's `derives-from`: this plan implements an amendment.
   - The license covers `lost` only, never `s`: a skip is never how behavior is removed. Another spec's loss is never licensed.
   - A licensed loss is no red. The detail and the reviewers' note name it, and the reviewers judge it.
5. **Not checked, and the base suite job (correction C32).** This is §3.5's rule for T3's test half: a round with no base counts reads "not checked", never green and never red. The check passes, its detail and the arbiter's facts say so, and `tests_effect` records why.
   - **The reasons:** the runner is filtered; no full-suite run happened this round (an implement whose parent names no test criterion, or a suite untrusted, cut short or unparsed); the base's code tree could not be read; the base suite is not measured yet (drive runs it); or it is not measured at all (no drive runs jobs here, two strikes, or scratch runs are off).
   - **A missing base is owed.** The check journals `owes: [{ kind: 'base-tests', key: '<base commit>.<suite>' }]`. The `base-tests` kind's `owed` reads it from in-progress plans' last implement and ship rounds: C13's on-demand rule, through a field any check can carry.
   - **The kind:** `turn: true` (it runs a suite), `gated: false` (no gate waits on it, so it yields the turn to plan work), `scratch: true`, `commands` = `ship.test`, and a box of `drive.sessionTimeoutMs` (a session's suite fits in one).
   - **Its shard** runs the suite on the base commit in the scratch, applies the load rule (row 258), and returns the per-spec summary with the commit, the commit's code tree and the tree it ran.
   - **A result that lands never moves a stop.** There is no `checksMoved` and nothing in the signature; the next round reads it. An implement round that read "not checked" is still read at ship.
   - With no drive, the base still comes from shipped summaries.
6. **Where it runs (correction C33).** Both code gates read the round's one suite run (row 252): implement's criteria lane hands its parsed suite out (`runCriteria`'s `onSuite`), and ship's tests lane already holds it. `switch-offs` moves to the end of the registry, after `drift-lane`. Every judged check runs whenever any does, and the signature sorts its terms, so the move changes no judgment, only where in `checks` the entry sits.
7. **The check and its booking.**
   - **A loss** is an `OffVerdict` variant, `{ kind: 'dropped', key, spec, count, base, plan }`. Its key is 16 hex over `['dropped', spec]`; `base` and `plan` are the spec's counts on each side. It is journaled in `switch-offs`'s `offs` after the token lines, sorted by spec, and `MAX_OFFS` counts both. `checksSignature` already reads every hit by key and unbooked copies.
   - **The detail** keeps T3a's line wording and appends the tests segment, one of: `tests: <spec> lost <n> (passed <b>→<p>, skipped <bs>→<ps>)` per loss (ten, then a count); `tests: <spec> lost <n> — licensed: its spec was amended since its last plan`; `tests: no spec lost a passing case (<k> compared)`; or `tests not checked — <why>`. Called without a tests effect (T3a's direct callers), the detail is exactly T3a's.
   - **The reviewers' note** gains a row per loss (`- tests of <spec> — <b> passing on the base, <p> here; skipped <bs> → <ps>`) and per licensed loss.
   - **The ledger's third kind**, `booked-dropped`, carries `spec`, `base: { passed, skipped }` (the booked round's base counts) and `subject: { cases }`. Its key is 16 hex over (kind, check, plan, spec, base passed, base skipped, cases); the other kinds' keys do not change. `bookingsOf` books each unbooked loss of a judged round, and the check applies the plan's own open items by spec (C17).
   - **The judge reads a loss as facts:** `tests of <spec>: <n> passing case(s) lost (skipped <bs>→<ps>)` and `tests not checked`. Spec ids are canon ids, spelled out; the judge never sees a test name or the suite's output. Rule `waivable`, the policy's hand-off to the arbiter and `--book switch-offs`' liveness stay as T3a built them; only their words widen to "line or spec".
   - **A booked loss closes when main has the cases back**, at the merge stamp of plan M, read from M's newest ship round's summary. M's own items close when the summary's counts for the spec are not short of the item's base: at least as many passed, at most as many skipped. An item of a plan merged before M closes only where the round's base counts were short and the summary is not, meaning this merge restored it. That base comes from `junit.base`, which ship now journals for each spec it compared; this is T3a's unit-review I1, applied to counts. A round with no summary observes nothing, and the abandon closes the plan's items as it does today.
8. **Left out, recorded (Open, in Task 8).**

## Review Focus

The input classes T3b's tests must not leave to chance, most likely first:

1. **A plan that adds passing cases for its spec and skips an old one.** The spec's passing count rises, and the new skip still reads red (C30). → Task 3, "three added and one skipped"; Task 4, "a plan that adds a passing case and skips an old one".
2. **A spec renamed or abandoned since the base.** Its base count is not compared, so there is no false loss. → Task 3, "a spec gone from canon is not compared".
3. **A summary from another suite command.** It is never the base, because its `suite` differs. The job is owed under today's suite, and a job asked under an older suite refuses. → Task 1, "a summary of another suite or other code is never the base"; Task 2, "a key whose suite changed since its gate asked".
4. **Main moved only by witness's own commits** (journal lines, stamps, canon, payload). The code tree still matches, the shipped summary serves, and nothing is owed. → Task 1, "main moved only by witness's own commits still finds it".
5. **Another plan's booked loss, at a merge whose round's base was cut before that plan merged.** It stays open, because the base counts were not short. → Task 7, "another merged plan's loss closes only where this round's base was short".
