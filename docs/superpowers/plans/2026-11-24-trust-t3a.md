# witness trust T3a — Switch-offs flagged, and the judge's booking — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A switch-off a plan adds — an `eslint-disable`, a `@ts-ignore`, an `it.skip(`, a `#[allow(` — is a judged red at implement and ship: the battery still runs and the reviewers are told, and the round's way on is the revise that removes it or a booking (`witness decide <gate> <plan> --book switch-offs`) that the AI judge or the human may take; a booked line is a ledger item that closes once main no longer holds the line.

**Architecture:** `src/switch-offs.ts` holds witness's token table (per language, each token where its tool reads it) and the scan: per file of the plan change set, the copies of each switch-off line beyond the base's. A new judged check, `switch-offs`, journals each line (`GateCheck.offs`) and applies the plan's own bookings. The ledger gains a second kind, `booked-switch-off` (subject: the line), booked on a round lenses ran through T2e's `--book` act, which `liveActs` now offers on a judged round whose only reds carry the judge's waiver. `recommend` gains rule `waivable`, which the policy hands to the arbiter; the arbiter books in-process, a typed booking keeps T2e's terminal and session rules. The merge stamp closes a booked line once the tree that merges no longer holds it.

**Tech Stack:** TypeScript (ESM, Node ≥ 20), vitest, the git CLI.

**Spec:** `docs/superpowers/specs/2026-11-21-trust-design.md` — §4 T3 (the token layer), §3.2 (judged tier; the switch-off waiver: "the AI judge or the human"), §3.3 (LD: booked-switch-off "closes when the line is gone"), §3.9 (the arbiter acts in-process; sessions cannot launder human acts), §6 (Train B's setting: switch-off extra patterns). The table (`TOKENS` in `src/switch-offs.ts`; its regexes are the probe's, Task 1):
   - **Directives** count only where they open a comment, as their tools honor them: `//` or `/*`, optional space, then ESLint's `eslint-disable`, `eslint-disable-line`, `eslint-disable-next-line`, its inline config (`/* eslint <rule>:`, block comments only), `@ts-ignore`, `@ts-expect-error`, `@ts-nocheck` (after any further `/` or `*`, as TypeScript reads `/// @ts-ignore` and `/** @ts-ignore */`), `biome-ignore`, `biome-ignore-all`, `biome-ignore-start`, `Stryker disable`; Python's `# noqa` (any case), `# type: ignore`, `# pylint: disable`; Go's `//nolint`. Prose naming a directive (`// see the eslint-disable docs`) is none.
   - **Code tokens** never count on a line that opens as a comment (`//`, `/*`, `*`; Python `#`): Rust's `#[allow(`, `#![allow(`, `#[expect(`, `#![expect(`, `cfg_attr(…` holding `allow(` or `expect(`, `#[ignore`, `mutants::skip`; and **in test files only** — a name with `.test.` or `.spec.` before its extension, or a path under a `test`, `tests`, `__tests__`, `spec` or `e2e` folder — the test API: `.skip`, `.only` or `.fails` followed by `(` or `.` (`it.skip.each(` counts, `.skipIf(` does not; a runtime `ctx.skip()` counts), `xit(`, `xtest(`, `xdescribe(` after no identifier character and no `.` (`process.exit(` never matches), and the options `skip: true`, `only: true`, `todo: true`, `fails: true`, `retry:` with a positive count. The three `true` options beside the spec's `fails:` are vitest's spellings of the listed methods; `retry:` and the options need their turning-on literal, so `retry: false`, `{ fails: "unreachable" }` and a variable value never match.
   - On this table fewhats shows no hit at all and witness only real ones (`ctx.skip()` in a fixture, two `@ts-expect-error`); every negative the probe lists stays out and every positive matches.
   - **The repo's own tokens** (`checks.switchOffs`, point 9): literal strings, never regexes (no ReDoS, nothing to escape), each matched on any line of any text file in PC, comment or code, where it is not glued to an identifier character on a side where the token itself has one; its id is `extra:<literal>`.
3. **A switch-off is a line, and only copies beyond the base's are the plan's (correction C27).** Per PC file, every line is scanned on the plan's version and on the base's (`gitBlob(wt, base, file)`; absent or unreadable reads empty — fail closed, every copy new); each hit is keyed 16 hex over (`switch-off`, token id, file, normalized line — `normalizeSnippet`, so a re-indented or CRLF line keeps its key); the plan adds the copies of a key beyond the base's count (base-red's per-key multiset, row 263) — the last ones, as `newDiagnostics` takes. So a moved or re-indented line is not new (a `-U0` diff would call it added), a duplicated one is, and a new file counts whole. A file that is not a regular text file (a symlink; a NUL in its first 8,000 bytes) is skipped, and a file holding no token anywhere costs no git call. Rule ids are read where the directive names them — ESLint's list up to ` -- `, Biome's category before `:`, a Rust attribute's list, `noqa:` codes, `type: ignore[…]`, `pylint: disable=`, `nolint:` — each `[@A-Za-z0-9_./:-]{1,100}`, at most 20, sorted.
